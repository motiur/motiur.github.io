AI for Accessibility

How AI can help disabled people hear, see, read and communicate, and how it can fail them: speech recognition and captions, sign language and lip reading, image description, reading support and AAC, with evaluation with users, fairness and deployment in Bangladesh.

  • Speech recognition
  • Captions
  • Sign language
  • Lip reading
  • Image description
  • Participatory design

Sessions

  1. 01

    Disability, accessibility and AI

    Compute WCAG contrast ratios from sRGB colours, find the nearest shade that passes, simulate colour vision deficiency with the Machado et al. (2009) matrices, and choose a chart palette that stays distinguishable.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  2. 02

    Speech recognition for Bangla

    Compute log-mel features with NumPy, train a small CTC speech recognizer on synthetic spoken digits with Bangla transcripts, and measure word and character error rates in clean and noisy conditions.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  3. 03

    Captions for deaf and hard-of-hearing viewers

    Align sequences with dynamic time warping and a transcript with CTC forced alignment, split timed words into readable caption blocks with dynamic programming, and write SubRip captions.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  4. 04

    Sign languages and hand pose

    Represent a hand as 21 landmarks, normalize them for position, size, rotation and handedness, and classify synthetic handshapes on signers the model has never seen.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  5. 05

    Recognizing isolated signs

    Train a recurrent network and a spatial–temporal graph network on synthetic landmark sequences, evaluate them on signers they have never seen, and test time-warp augmentation.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  6. 06

    Continuous signing and sign language translation

    Train a CTC recognizer on synthetic continuous signing, decode it greedily and with prefix beam search and a gloss language model, and score translations with BLEU and chrF written from scratch.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  7. 07

    Lip reading

    Build synthetic lip-landmark videos with homophenes, train a graph attention lip reader on unseen speakers, and measure how adding noisy audio helps, with early and late fusion.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  8. 08

    Describing images for blind and low-vision users

    Detect blurry, dark, over-exposed and badly framed photos, train a tiny CLIP-style model that matches digit images to short descriptions, and make it abstain when it is unsure.

    Read notebook Colab Kaggle .ipynb 2 NOT RUN cells
  9. 09

    Reading support: OCR, text-to-speech and simplification

    Train a digit classifier and a CTC line recognizer, compare them with segmentation on lines joined like Bangla words, normalize text for a speech synthesizer, and check a simplified text for changed facts.

    Read notebook Colab Kaggle .ipynb 2 NOT RUN cells
  10. 10

    Augmentative and alternative communication

    Measure keystroke savings from word prediction with 1, 3 and 5 suggestions, estimate the information per letter with character n-grams, and compare row-column switch scanning layouts with predictive scanning.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  11. 11

    Evaluation, fairness and participatory design

    Report a recognizer's accuracy for each group of users with bootstrap intervals, estimate by simulation how many test examples a fair comparison needs, score the System Usability Scale, and write a per-group error report.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  12. 12

    Deploying accessible AI in Bangladesh, and the capstone

    Train a small isolated-sign recognizer, shrink it with dynamic int8 quantization, measure size, single-thread latency and accuracy before and after, and add a confidence threshold that asks the user to sign again.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell

Before you start

One notebook per session. Read them with their saved outputs on the course website or on GitHub, or open them in Google Colab or Kaggle Notebooks and run them from the top.

  • Every cell without a NOT RUN label was run once, top to bottom, on a CPU in November 2026 (Python 3.13, NumPy 2.5, SciPy 1.18, pandas 3.0, scikit-learn 1.9 and matplotlib 3.11, plus PyTorch 2.15 in sessions 2, 5–9 and 12), and the outputs are saved in the notebooks. A second, independent run reproduced every printed number; only timings differ.
  • The labs use synthetic data generated in the notebooks, so they run anywhere without downloads or recordings of real people: tone-based "speech", word timestamps, 21-point hand skeletons and sign sequences, lip-landmark sequences, degraded photos made from scikit-learn's sample images, digits from scikit-learn standing in for handwritten Bangla digits, and a short English text for word prediction. The numbers show how the methods behave; they are not results on real disabled users, and the course says so wherever it matters.
  • Cells marked TODO are exercises for students. Cells marked NOT RUN need a download, a GPU or a library that is not installed here (Whisper, WhisperX, MediaPipe, an Auto-AVSR checkpoint, BLIP, Tesseract with Bengali data, NumtaDB, ONNX Runtime); they were written from the tools' documented interfaces and have not been executed, so run each one before recording (the table below says what each needs).
  • Nothing extra needs installing for the runnable cells on Google Colab or Kaggle.
  • Results that went against expectation are stated in each notebook's "What to notice" cell and in the course document. Examples: the colour palette designed for colour-blind readers has three colours below WCAG's 3:1 contrast on white (session 1); the dynamic-programming caption segmenter left more blocks over the reading-speed limit than the greedy one, although its line breaks were far better (session 3); the small skeleton graph network did worse than a GRU on new signers, and time-warp augmentation did not help (session 5); jointly trained audio-visual fusion fell below video alone in heavy noise, while late fusion was best or tied (session 7); a confidence margin still answered most damaged inputs (session 8); a group's accuracy measured on 40 examples missed its true value (session 11); int8 quantization shrank the sign model 3.4 times but barely changed its speed (session 12).
