1. The text¶

People who cannot rely on speech may communicate with augmentative and alternative communication (AAC): symbol boards, letter boards, or a speech-generating device that speaks what they select. Every selection costs time and effort, so AAC software predicts what comes next. To measure prediction we need text. Below is a short everyday English text written for this course (a student's week, plus common messages; free to reuse). Real predictors learn from millions of words and, best of all, from the user's own messages; ours learns from about 1,800.

We train on the first 80% of the words and test on the last 20%, so the test text is "the future".

2. Word prediction and keystroke savings¶

A word predictor shows a list of $k$ suggestions while the user types. Before each keystroke the list holds the $k$ most likely words that start with the letters typed so far; if the wanted word is there, one selection enters it (and its space). We compare two predictors:

  • unigram: rank words by how often they appear in the training text;
  • bigram: rank by $P(w \mid \text{previous word})$, interpolated with the unigram: $0.8\,\frac{C(\text{prev}, w)}{C(\text{prev})} + 0.2\,\frac{C(w)}{N}$.

Keystroke savings (KS) is $1 - \frac{\text{keystrokes with prediction}}{\text{keystrokes without}}$, where typing without prediction costs one keystroke per letter plus one for the space.

uni = Counter(train_words)
bi = defaultdict(Counter)
for a, b in zip(train_words, train_words[1:]):
    bi[a][b] += 1
bi_total = {a: sum(c.values()) for a, c in bi.items()}
vocab, N = sorted(uni), len(train_words)

def suggestions(prev, prefix, k, use_context):
    def score(w):
        p = uni[w] / N
        if use_context and prev in bi:
            p = 0.8 * bi[prev][w] / bi_total[prev] + 0.2 * p
        return p
    return heapq.nlargest(k, (w for w in vocab if w.startswith(prefix)), key=score)

def count_keystrokes(text_words, k, use_context=True):
    keys, prev = 0, None
    for w in text_words:
        typed = ""
        while True:
            if k > 0 and w in suggestions(prev, typed, k, use_context):
                keys += 1; break                  # select the word from the list
            if typed == w:
                keys += 1; break                  # the word is fully typed: press space
            typed += w[len(typed)]; keys += 1     # type the next letter
        prev = w
    return keys

baseline = sum(len(w) + 1 for w in test_words)
ks = {name: [1 - count_keystrokes(test_words, k, ctx) / baseline for k in range(11)]
      for name, ctx in [("unigram", False), ("bigram", True)]}
print(f"test text: {baseline} keystrokes without prediction")

3. Do more suggestions always help?¶

Keystrokes are not time. Before every keystroke the user must look through the list to see whether the word is there, and a longer list takes longer to read. A simple model: one keystroke costs 1 unit of time, and reading one suggestion costs $r$ units, so

$$\text{time} = \text{keystrokes} \times (1 + r k).$$

The reading cost $r$ is an assumption here; it depends on the person, the access method and the screen, and in a real study you would measure it. We try $r$ = 0, 0.1 and 0.25 and report the time relative to typing without prediction.

keys_bigram = [baseline * (1 - v) for v in ks["bigram"]]
fig, ax = plt.subplots(1, 2, figsize=(9, 3.3))

    ax[0].plot(range(11), v, "o-", label=name)

ax[0].legend(fontsize=8)
for r in [0.0, 0.1, 0.25]:
    rel_time = [keys_bigram[k] * (1 + r * k) / baseline for k in range(11)]
    best = int(np.argmin(rel_time))
    print(f"reading cost r = {r:.2f}: best k = {best}, time {rel_time[best]:.3f} of typing without prediction; "

4. How much information is in a letter? Character n-grams¶

Information theory (Course 2 session 11) says how many yes/no decisions a selection is worth. Choosing one of 27 symbols (26 letters and the space) uniformly carries $\log_2 27 = 4.75$ bits, but text is predictable. A character n-gram model predicts each symbol from the $n-1$ symbols before it. We train models of order 1 to 5 with Witten–Bell smoothing (each order backs off to the one below) and measure their cross-entropy on the test text, in bits per character: the average of $-\log_2 p(\text{true symbol})$. Shannon estimated that a good model of English needs only about one bit per letter (Shannon 1951); with 1,800 words of training text we will not get close.

train_chars = " ".join(train_words) + " "
test_chars = " ".join(test_words) + " "
ALPHABET = "abcdefghijklmnopqrstuvwxyz "

class CharNgram:
    def __init__(self, text, order):
        self.order = order
        self.counts = [defaultdict(Counter) for _ in range(order)]      # counts[m][context of length m][next symbol]
        for i in range(len(text)):
            for m in range(order):
                if i - m >= 0:
                    self.counts[m][text[i - m:i]][text[i]] += 1

    def probs(self, history):
        p = np.full(len(ALPHABET), 1 / len(ALPHABET))                  # start from uniform
        for m in range(self.order):                                     # Witten-Bell: mix in longer contexts
            ctx = history[len(history) - m:] if m else ""
            if m > len(history) or ctx not in self.counts[m]:
                break
            c = self.counts[m][ctx]
            total, types = sum(c.values()), len(c)
            lam = total / (total + types)
            p = lam * np.array([c[s] for s in ALPHABET]) / total + (1 - lam) * p
        return p

def bits_per_char(model, text):
    return np.mean([-np.log2(model.probs(text[max(0, i - 6):i])[ALPHABET.index(text[i])]) for i in range(len(text))])

models = {n: CharNgram(train_chars, n) for n in range(1, 6)}
bpc = {n: bits_per_char(m, test_chars) for n, m in models.items()}
print(f"uniform over 27 symbols: {np.log2(27):.2f} bits per character")
for n, b in bpc.items():
    print(f"order {n} ({n - 1} symbol{'' if n == 2 else 's'} of context): {b:.2f} bits per character on the test text")

5. Switch scanning: the layout matters¶

Some people select with a single switch: a button pressed with a hand, the head or a foot. In row–column scanning the rows of a letter grid light up one after another; the user presses when the right row lights, then the cells of that row light up, and the user presses again. A symbol in row $i$ and column $j$ (counting from 1) costs $i + j$ scan steps. We compare an alphabetical 5 × 6 grid with a frequency-ordered grid that puts the most common symbols in the cheapest cells, and count the average steps per character of the test text. If one scan step takes 1 second (an assumption; users set their own speed), steps per character are also seconds per character.

ROWS, COLS = 5, 6
cost = np.add.outer(np.arange(1, ROWS + 1), np.arange(1, COLS + 1))           # i + j scan steps
cells = sorted(((r, c) for r in range(ROWS) for c in range(COLS)), key=lambda rc: (cost[rc], rc[0]))
freq = Counter(train_chars)
layouts = {"alphabetical": {s: (i // COLS, i % COLS) for i, s in enumerate("abcdefghijklmnopqrstuvwxyz ")},
           "frequency-ordered": {s: cells[i] for i, s in enumerate(sorted(ALPHABET, key=lambda s: -freq[s]))}}
steps = {name: np.mean([cost[lay[ch]] for ch in test_chars]) for name, lay in layouts.items()}
chars_per_word = len(test_chars) / len(test_words)
for name, s in steps.items():
    print(f"{name:17s}: {s:.2f} scan steps per character; at 1 step per second, {60 / (s * chars_per_word):.1f} words per minute")

fig, ax = plt.subplots(1, 2, figsize=(9, 3.0))
for a, (name, lay) in zip(ax, layouts.items()):
    a.imshow(cost, cmap="Blues", vmin=1, vmax=ROWS + COLS + 2)
    for s, (r, c) in lay.items():
        a.text(c, r, "space" if s == " " else s, ha="center", va="center", fontsize=8 if s == " " else 11)
    a.set_xticks([]); a.set_yticks([]); a.set_title(f"{name}: {steps[name]:.2f} steps per character", fontsize=10)
plt.tight_layout(); plt.show()

6. Predictive scanning, Huffman codes and bits per step¶

Each scan step ends in one of two outcomes (press or wait), so it can carry at most 1 bit. A layout is efficient if each step carries close to 1 bit. Two better schemes:

  • Huffman scanning: give each symbol a sequence of yes/no questions from a Huffman code (Huffman 1952) built on symbol frequencies. It is the best prefix code for those frequencies, like the code 0, 10, 110, 111 in Course 2 session 11, and its average length is within 1 of the entropy.
  • Predictive scanning: before each character, reorder the symbols by the order-4 character model's probabilities and scan them one at a time; or build a fresh Huffman code from those probabilities. Dasher (Ward, Blackwell & MacKay 2000) uses the same idea continuously: it gives each possible next letter screen space in proportion to its probability.

We report steps per character and bits per step, using the order-4 model's cross-entropy as the estimate of the information in each character.

def huffman_lengths(p):
    heap = [(q, i, [i]) for i, q in enumerate(p)]
    heapq.heapify(heap)
    lengths, tie = np.zeros(len(p), int), len(p)
    while len(heap) > 1:
        q1, _, a = heapq.heappop(heap); q2, _, b = heapq.heappop(heap)
        lengths[a + b] += 1                       # every symbol under the merged node gets one more question
        heapq.heappush(heap, (q1 + q2, tie, a + b)); tie += 1
    return lengths

p_uni = np.array([freq[s] + 1 for s in ALPHABET], float); p_uni /= p_uni.sum()
huff = huffman_lengths(p_uni)
m4 = models[4]
pred_linear, pred_huff = [], []
for i, ch in enumerate(test_chars):
    p = m4.probs(test_chars[max(0, i - 6):i])
    target = ALPHABET.index(ch)
    pred_linear.append(1 + int((p > p[target]).sum()))           # rank of the true symbol when scanned in order of probability
    pred_huff.append(huffman_lengths(p)[target])
results = {"alphabetical rows/columns": steps["alphabetical"], "frequency rows/columns": steps["frequency-ordered"],
           "Huffman on letter frequencies": np.mean([huff[ALPHABET.index(ch)] for ch in test_chars]),
           "predictive, one at a time": np.mean(pred_linear), "predictive Huffman": np.mean(pred_huff)}
info = bpc[4]

    print(f"{name:30s}: {s:5.2f} steps per character, {info / s:.2f} bits per step, "
          f"{60 / (s * chars_per_word):4.1f} words per minute at 1 step per second")

What to notice¶

(Written from the run above; the numbers are exact if you keep the text unchanged.)

  1. A predictor cannot suggest what it has never seen. The text has 2,259 words (466 different), and 93 of the 452 test words (21%) never appear in the 1,807 training words. A user's own names, places and topics are often exactly such words, which is why personal vocabulary matters.
  2. Prediction saves keystrokes, with fast-shrinking returns. The bigram predictor saved 0.289, 0.386 and 0.421 of the keystrokes with 1, 3 and 5 suggestions; the unigram saved 0.245, 0.350 and 0.386, so the previous word added about 4 points. Going from 5 to 10 suggestions only raised the bigram's savings from 0.421 to 0.463.
  3. More suggestions can make typing slower. If reading the list were free ($r = 0$), 10 suggestions would be best (0.537 of the time). With $r = 0.1$ the best was 2 suggestions (0.778 of the time), and 10 suggestions were slower than no prediction at all (1.075). With $r = 0.25$ the best was 1 suggestion (0.889), and 5 suggestions took 1.303 times as long. The values of $r$ are assumptions: measure them with each user.
  4. Letters carry fewer bits than the alphabet suggests. A uniform choice among 27 symbols is 4.75 bits; the order-1 model needed 4.00 bits per character on the test text and the order-4 model 2.63. Against expectation, order 5 did slightly worse (2.66): with 1,800 words of training text most 4-letter contexts are rare, so the longer model has too little data. Reaching Shannon's estimate of about one bit per letter needs far more text.
  5. Layout matters for switch users. The frequency-ordered grid needed 4.16 scan steps per character against 6.07 for the alphabetical grid, 31% fewer: at an assumed 1 step per second, 3.0 instead of 2.1 words per minute.
  6. Prediction approaches the information limit. A Huffman code on letter frequencies needed 4.04 steps per character, close to the unigram limit of 4.00, so the frequency grid (4.16) was already nearly as good as any scheme without context. Prediction did better: 3.39 steps when letters are offered one at a time in order of probability, and 2.67 with a fresh Huffman code before every letter, which is 0.99 bits per step, almost the 1-bit maximum of a yes/no step. Even then, at 4.7 words per minute a ten-word reply takes about two minutes.
