1. Five ways a photo goes wrong¶

A blind person who photographs a letter, a medicine box or a bus sign cannot check the photo before asking a question about it. In VizWiz, a dataset of photos and spoken questions from blind people, many photos are blurry, too dark or badly framed, and many questions cannot be answered from the photo at all (Gurari et al. 2018). So a describing system should first check the photo and tell the user how to fix it.

We cut 128 × 128 grey crops from scikit-learn's two sample photos (china.jpg and flower.jpg) and damage them in four ways: defocus blur (a Gaussian blur), motion blur (averaging along a line, as when the hand moves), too dark (scaling all pixels down) and too bright (scaling up until 40–80% of the pixels clip at white). Every crop also gets a little sensor noise. Three numbers describe each crop:

  • the variance of the Laplacian, a classic focus measure: the Laplacian responds to edges, and blur removes edges (we use its base-10 logarithm);
  • the mean brightness, from 0 (black) to 1 (white);
  • the fraction of clipped pixels, those at or near pure white.

torch.set_num_threads(1)
t_start = time.time()

def grey(img):                                   # sRGB values to a 0-1 grey image (luminance weights)
    return (img.astype(float) @ np.array([0.2126, 0.7152, 0.0722])) / 255.0

photos = {"china": grey(load_sample_image("china.jpg")), "flower": grey(load_sample_image("flower.jpg"))}

def motion_kernel(length, angle):
    c = length // 2
    k = np.zeros((2 * c + 1, 2 * c + 1))
    for t in np.linspace(-c, c, 4 * length):
        k[int(round(c + t * np.sin(angle))), int(round(c + t * np.cos(angle)))] = 1
    return k / k.sum()

CONDITIONS = ["good", "defocus blur", "motion blur", "too dark", "too bright"]

def damage(crop, cond, rng):
    if cond == "defocus blur":
        out = ndimage.gaussian_filter(crop, rng.uniform(1.5, 3.0))
    elif cond == "motion blur":
        out = ndimage.convolve(crop, motion_kernel(int(rng.integers(9, 16)), rng.uniform(0, np.pi)), mode="reflect")
    elif cond == "too dark":
        out = crop * rng.uniform(0.06, 0.15)
    elif cond == "too bright":                    # scale up until a fraction p of the pixels reach white
        p = rng.uniform(0.4, 0.8)
        out = crop / max(np.quantile(crop, 1 - p), 0.05)
    else:
        out = crop
    return np.clip(out + rng.normal(0, 0.005, crop.shape), 0, 1)

def features(img):
    focus = np.log10(ndimage.laplace(img).var() + 1e-6)          # log10 variance of the Laplacian
    return np.array([focus, img.mean(), (img >= 0.98).mean()])

def make_crops(name, n, seed):
    rng, im = np.random.default_rng(seed), photos[name]
    feats, conds, crops = [], [], []
    for i in range(n):
        y0, x0 = rng.integers(0, im.shape[0] - 128), rng.integers(0, im.shape[1] - 128)
        cond = CONDITIONS[i % 5]
        crop = damage(im[y0:y0 + 128, x0:x0 + 128], cond, rng)
        feats.append(features(crop)); conds.append(cond); crops.append(crop)
    return np.array(feats), np.array(conds), crops

F_tune, C_tune, crops_tune = make_crops("china", 300, seed=1)     # used to choose thresholds
F_test, C_test, _ = make_crops("china", 300, seed=2)              # new crops of the same photo
F_new, C_new, _ = make_crops("flower", 300, seed=3)               # a different photo

print("china crops used for tuning: mean of each measure per condition")
print(f"{'condition':14s} {'log10 focus':>12s} {'brightness':>11s} {'clipped':>8s}")
for c in CONDITIONS:
    m = F_tune[C_tune == c].mean(0)
    print(f"{c:14s} {m[0]:12.2f} {m[1]:11.3f} {m[2]:8.3f}")

fig, ax = plt.subplots(1, 5, figsize=(9, 2.3))
for a, c in zip(ax, CONDITIONS):

    a.imshow(crops_tune[i], cmap="gray", vmin=0, vmax=1); a.axis("off")
    a.set_title(f"{c}\nfocus {F_tune[i, 0]:.2f}, mean {F_tune[i, 1]:.2f}", fontsize=8)

2. Choosing thresholds on one set, testing on another¶

The checks run in order: too dark if the mean brightness is below $t_\text{dark}$; otherwise too bright if the clipped fraction is above $t_\text{bright}$; otherwise blurry if the focus measure is below $t_\text{blur}$; otherwise good. Each threshold is chosen on the china tuning crops to maximize balanced accuracy (the average of the two per-class accuracies). Then we test on new china crops (the same kind of scene) and on flower crops (a new scene, with a soft background and dark leaves). Before running: which do you expect to be harder, and why?

def best_threshold(x, positive):
    # positive = True where the problem is present and x is LOW (we flag x < t); maximize balanced accuracy
    cands = np.unique(x)
    bal = [((x[positive] < t).mean() + (x[~positive] >= t).mean()) / 2 for t in cands]
    return cands[int(np.argmax(bal))]

t_dark = best_threshold(F_tune[:, 1], C_tune == "too dark")
t_bright = -best_threshold(-F_tune[:, 2], C_tune == "too bright")
exposed_ok = (F_tune[:, 1] >= t_dark) & (F_tune[:, 2] <= t_bright)
blurred = np.isin(C_tune, ["defocus blur", "motion blur"])
t_blur = best_threshold(F_tune[exposed_ok, 0], blurred[exposed_ok])
print(f"thresholds chosen on china tuning crops: dark if mean < {t_dark:.3f}; bright if clipped > {t_bright:.3f}; "
      f"blurry if focus < {t_blur:.2f}")

def check_photo(f):
    if f[1] < t_dark: return "too dark"
    if f[2] > t_bright: return "too bright"
    if f[0] < t_blur: return "blurry"
    return "good"

truth = lambda C: np.where(np.isin(C, ["defocus blur", "motion blur"]), "blurry", C)
for name, Fx, Cx in [("china, tuning", F_tune, C_tune), ("china, new crops", F_test, C_test), ("flower, new scene", F_new, C_new)]:

    print(f"{name:18s}: correct verdict {np.mean(pred == tr):.3f}; good photos rejected {np.mean(pred[tr == 'good'] != 'good'):.3f}; "
          f"damaged photos accepted {np.mean(pred[tr != 'good'] == 'good'):.3f}")
pred_new = np.array([check_photo(f) for f in F_new])
verdicts, counts = np.unique(pred_new[C_new == "good"], return_counts=True)
print("flower: verdicts given to the 60 good crops:", {str(v): int(c) for v, c in zip(verdicts, counts)})

fig, ax = plt.subplots(1, 2, figsize=(9, 3.2), sharey=True)

3. A tiny CLIP: matching images to descriptions¶

CLIP (Radford et al. 2021; Course 4 session 9) trains an image encoder and a text encoder so that a matching image and caption get similar unit-length embeddings. For a batch of $n$ pairs it computes all $n \times n$ cosine similarities, scales them by a learned factor $1/\tau$, and applies cross-entropy in both directions: each image must pick its caption, and each caption its image.

Our version pairs 8 × 8 digits (load_digits, placed in the middle of a 12 × 12 frame) with short template descriptions such as "a handwritten seven", "the digit seven" or "7". The image encoder is a small MLP; the text encoder averages learned word embeddings. With only ten digits, a batch often contains the same caption twice, so we count every identical caption as a correct match (soft targets). Real systems train on hundreds of millions of web image–text pairs; this one trains on 1,000 images in a few seconds.

Then we describe test images by retrieval: compare each image with one description per digit and pick the most similar. We try every template, including one never seen in training.

X_dig, y_dig = load_digits(return_X_y=True)
X_dig = X_dig.reshape(-1, 8, 8) / 16.0
S = 12                                                    # frame size: the digit sits 2 pixels from each edge

def frame(img, dx=0, dy=0):
    out = np.zeros((S, S))
    x0, y0 = 2 + dx, 2 + dy                               # shifted digits lose the part that leaves the frame
    xs, ys, xe, ye = max(0, x0), max(0, y0), min(S, x0 + 8), min(S, y0 + 8)
    out[ys:ye, xs:xe] = img[ys - y0:ye - y0, xs - x0:xe - x0]
    return out

NAMES = ["zero", "one", "two", "three", "four", "five", "six", "seven", "eight", "nine"]
TEMPLATES = ["a handwritten {w}", "the digit {w}", "the number {d}", "{d}", "a photo of the number {w}"]
UNSEEN = "an image showing a {w}"
vocab = {w: i + 1 for i, w in enumerate(sorted({t for tp in TEMPLATES for d in range(10)
                                                 for t in tp.format(w=NAMES[d], d=d).split()}))}   # 0 = unknown word

def encode_text_batch(captions):
    ids = [[vocab.get(t, 0) for t in c.split()] for c in captions]
    offsets = np.cumsum([0] + [len(i) for i in ids[:-1]])
    return torch.tensor(sum(ids, [])), torch.tensor(offsets)

class TinyCLIP(nn.Module):
    def __init__(self, d=32):
        super().__init__()
        self.image = nn.Sequential(nn.Linear(S * S, 128), nn.ReLU(), nn.Linear(128, d))
        self.words = nn.EmbeddingBag(len(vocab) + 1, d, mode="mean")
        self.text = nn.Linear(d, d)
        self.log_scale = nn.Parameter(torch.tensor(np.log(1 / 0.07), dtype=torch.float32))   # CLIP's starting temperature
    def embed_images(self, x):
        return F.normalize(self.image(torch.as_tensor(x, dtype=torch.float32)), dim=-1)
    def embed_texts(self, captions):
        return F.normalize(self.text(self.words(*encode_text_batch(captions))), dim=-1)

rng = np.random.default_rng(0)
perm = rng.permutation(len(y_dig))
i_tr, i_va, i_te = perm[:1000], perm[1000:1400], perm[1400:]
frames = lambda idx, rng=None: np.array([frame(X_dig[i], *(rng.integers(-1, 2, 2) if rng is not None else (0, 0)))
                                         for i in idx]).reshape(len(idx), -1)

clip = TinyCLIP()
opt = torch.optim.Adam(clip.parameters(), lr=3e-3)
gen = np.random.default_rng(1)
t0 = time.time()
for epoch in range(60):
    order = gen.permutation(i_tr)
    for b in range(0, len(order), 100):
        idx = order[b:b + 100]
        caps = [TEMPLATES[gen.integers(len(TEMPLATES))].format(w=NAMES[y_dig[j]], d=y_dig[j]) for j in idx]
        logits = clip.log_scale.exp() * clip.embed_images(frames(idx, gen)) @ clip.embed_texts(caps).T   # jitter by 1 pixel
        same = torch.tensor([[a == c for c in caps] for a in caps], dtype=torch.float32)
        target = same / same.sum(1, keepdim=True)                                   # identical captions share the credit
        loss = -0.5 * ((target * F.log_softmax(logits, 1)).sum(1).mean() + (target * F.log_softmax(logits.T, 1)).sum(1).mean())
        opt.zero_grad(); loss.backward(); opt.step()
print(f"trained in {time.time() - t0:.1f} s; learned temperature tau = {1 / clip.log_scale.exp().item():.3f}")

def similarities(x, template="a handwritten {w}"):
    with torch.no_grad():
        return (clip.embed_images(x) @ clip.embed_texts([template.format(w=NAMES[d], d=d) for d in range(10)]).T).numpy()

X_va, X_te = frames(i_va), frames(i_te)
for tp in TEMPLATES + [UNSEEN]:
    acc = (similarities(X_te, tp).argmax(1) == y_dig[i_te]).mean()
    print(f"descriptions written as {tp!r:30s} test accuracy {acc:.3f}" + ("   (template never seen in training)" if tp == UNSEEN else ""))

4. Saying "I am not sure": selective prediction¶

A model that must always answer will answer wrongly. Selective prediction lets it abstain (Chow 1970; Geifman & El-Yaniv 2017). Our confidence score is the margin: the similarity of the best description minus that of the second best. We pick the smallest margin threshold whose answered validation images are at least 99% correct, then report on the test set the coverage (the share of images answered) and the accuracy on those answered. Calibration and conformal prediction, two more careful tools, are in Course 3 session 12.

Then the hard part: inputs unlike the training data. We test three kinds: digits cut off by the frame (shifted 3 or 4 pixels sideways), digits blurred with added noise, and 12 × 12 patches of the sample photos that contain no digit at all, the analogue of a VizWiz question that cannot be answered.

def margin_and_pred(x):
    s = np.sort(similarities(x), 1)
    return s[:, -1] - s[:, -2], similarities(x).argmax(1)

m_va, p_va = margin_and_pred(X_va)
order = np.argsort(-m_va)
running_acc = np.cumsum(p_va[order] == y_dig[i_va][order]) / np.arange(1, len(order) + 1)
k = np.where(running_acc >= 0.99)[0].max()                      # the most images we can answer at >= 99% accuracy
threshold = m_va[order][k]
print(f"margin threshold {threshold:.3f}, chosen on validation (coverage there {(k + 1) / len(order):.3f})")

rng = np.random.default_rng(4)
tests = {"clean digits": (X_te, y_dig[i_te]),
         "cut off by the frame": (np.array([frame(X_dig[i], rng.choice([-4, -3, 3, 4]), 0) for i in i_te]).reshape(len(i_te), -1), y_dig[i_te]),
         "blurred + noise": (np.array([np.clip(ndimage.gaussian_filter(frame(X_dig[i]), 0.7) + rng.normal(0, 0.05, (S, S)), 0, 1)
                                       for i in i_te]).reshape(len(i_te), -1), y_dig[i_te])}
patches = []
for name in ["china", "flower"]:
    for _ in range(200):
        y0, x0 = rng.integers(0, photos[name].shape[0] - 48), rng.integers(0, photos[name].shape[1] - 48)
        p = photos[name][y0:y0 + 48, x0:x0 + 48].reshape(S, 4, S, 4).mean((1, 3))   # shrink 48 x 48 to 12 x 12
        patches.append((p - p.min()) / (p.max() - p.min() + 1e-6))
tests["no digit (photo patches)"] = (np.array(patches).reshape(len(patches), -1), None)

curves = {}
for name, (x, y_true) in tests.items():
    m, p = margin_and_pred(x)
    answered = m >= threshold
    if y_true is None:
        print(f"{name:24s}: answered {answered.mean():.3f} of them (every answer is wrong: there is no digit)")
        continue
    correct = p == y_true
    print(f"{name:24s}: accuracy if always answering {correct.mean():.3f}; answered {answered.mean():.3f}; "
          f"accuracy on answered {correct[answered].mean():.3f}")
    o = np.argsort(-m)
    curves[name] = (np.arange(1, len(o) + 1) / len(o), np.cumsum(correct[o]) / np.arange(1, len(o) + 1))

plt.figure(figsize=(6.5, 3.4))
for name, (cov, acc) in curves.items():
    plt.plot(cov, acc, label=name)
plt.axhline(0.99, color="0.5", ls=":", lw=1)
plt.xlabel("coverage (share of images answered, most confident first)"); plt.ylabel("accuracy on answered")
plt.title("abstaining helps on familiar inputs, much less on damaged ones", fontsize=10); plt.legend(fontsize=8)
plt.tight_layout(); plt.show()

5. Guiding the user instead of guessing¶

Putting it together: before describing, check the framing. A digit with ink on the edge of the frame is probably cut off, and the side says which way to move the camera. Only then use the model, and abstain when the margin is small. The cell measures the framing check on the cut-off and clean digits, then prints the message a user would hear for a few examples.

def framing(img):
    ink = img.reshape(S, S) > 0.3                               # ink-like pixels only, so faint noise does not count
    edge = {"left": ink[:, 0].sum(), "right": ink[:, -1].sum(), "top": ink[0].sum(), "bottom": ink[-1].sum()}
    side = max(edge, key=edge.get)
    return side if edge[side] >= 2 else None                    # at least 2 ink pixels on one edge of the frame

for name in ["clean digits", "cut off by the frame", "blurred + noise"]:
    flagged = np.mean([framing(x) is not None for x in tests[name][0]])
    print(f"framing check flags {flagged:.3f} of the '{name}' images")

MOVE = {"left": "to the left", "right": "to the right", "top": "up", "bottom": "down"}
a_or_an = lambda w: ("an " if w == "eight" else "a ") + w

def describe(img):
    side = framing(img)
    if side is not None:
        return f"The object is cut off at the {side}. Move the camera {MOVE[side]} and try again."
    s = similarities(img.reshape(1, -1))[0]
    best, second = np.argsort(-s)[:2]
    if s[best] - s[second] < threshold:
        return f"I am not sure. It may be {a_or_an(NAMES[best])} or {a_or_an(NAMES[second])}. Please take another photo."
    return f"This looks like a handwritten {NAMES[best]}."

examples = [("clean", tests["clean digits"][0][0], y_dig[i_te][0]), ("cut off", tests["cut off by the frame"][0][1], y_dig[i_te][1]),
            ("blurred", tests["blurred + noise"][0][2], y_dig[i_te][2]), ("blurred", tests["blurred + noise"][0][5], y_dig[i_te][5]),
            ("no digit", tests["no digit (photo patches)"][0][0], None)]
for kind, img, true in examples:
    print(f"[{kind:8s} true: {NAMES[true] if true is not None else 'none':5s}] {describe(img)}")
print(f"runtime so far {time.time() - t_start:.0f} s")

What to notice¶

(Written from the run above; your numbers will match if you keep the seeds.)

  1. Simple photo checks work on the scene they were tuned on, and fail on a new one. The thresholds chosen on china crops (dark if the mean is below 0.205, bright if more than 0.223 of the pixels clip, blurry if the focus measure is below −1.60) gave the correct verdict for 0.947 of new china crops and accepted only 0.004 of the damaged ones, but they rejected 0.250 of the good ones: plain areas such as sky have few edges and look blurry. On the flower photo they rejected 0.817 of the good crops (32 of 60 called blurry, 17 too dark), because its soft background and dark leaves look like blur and darkness. The variance of the Laplacian measures edges, not focus.
  2. The tiny CLIP describes digits well, and the wording matters. It trained in about 3 seconds and picked the right description for 0.950 to 0.957 of the test digits with the five training templates, but only 0.904 with a template it had never seen. Prompt wording changes results in real CLIP models too (Course 4 session 9).
  3. Abstaining works on familiar inputs. The margin threshold chosen on validation images (0.122) answered 0.912 of the clean test digits with accuracy 0.986, up from 0.957 when always answering. That is a little below the 0.99 aimed for on validation: a threshold chosen on 400 images is itself uncertain.
  4. Confidence does not detect damaged or foreign inputs. For digits cut off by the frame, the model still answered 0.668 of them, and only 0.140 of those answers were right; for blurred, noisy digits it answered 0.657 with accuracy 0.322; and it described 0.593 of the photo patches, which contain no digit at all, as a digit. Its curves for damaged inputs stay low at every coverage. This is "a fluent description is not a correct description" in numbers.
  5. Checking the input helps, but every check has blind spots. The framing check caught 0.705 of the cut-off digits with no false alarms on clean or blurred digits. Yet in the examples a blurred seven was confidently called an eight, and a photo patch with no digit was told to "move the camera down". A real system needs several checks, tuned on real photos from blind users, and should tell the user what it could not do.
