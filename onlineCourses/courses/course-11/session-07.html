1. A small CNN with batch normalization¶

We train a small convolutional network (CNN) on scikit-learn's digits: 8 × 8 images, upsampled to 16 × 16 by repeating each pixel. Each convolution is followed by batch normalization (BN). This is the training graph we want to deploy. A real phone model would see camera images and be larger; the steps are the same.

Colab and Kaggle: this notebook needs ONNX and ONNX Runtime. Run pip install onnx onnxscript onnxruntime in a cell first (they were already installed on the machine that ran this notebook).

About the timings: every timing here is single-thread (torch.set_num_threads(1), and one thread in ONNX Runtime), the median of 500 runs after 50 warm-up runs. They were measured on a shared server CPU in a container (an Intel Xeon with AVX-512 vector instructions), not on a phone, so read them as relative comparisons on this machine. Your numbers will differ. Session 11 builds a careful benchmark harness.

import os, time, copy, logging, platform, tempfile
import numpy as np
import torch, torch.nn as nn, torch.nn.functional as F
import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
import onnx, onnxruntime as ort
from onnx import numpy_helper
from onnxruntime.quantization import quantize_dynamic, QuantType
from onnxruntime.quantization.shape_inference import quant_pre_process

t_start = time.time()
torch.set_num_threads(1); torch.manual_seed(0); np.random.seed(0)
logging.getLogger("torch.onnx._internal.exporter._registration").setLevel(logging.ERROR)  # hides "torchvision is not installed" notes
TMP = tempfile.mkdtemp(prefix="c14_s07_")             # exported files go to a temporary folder

X, y = load_digits(return_X_y=True)
X = np.kron(X.reshape(-1, 8, 8) / 16.0, np.ones((1, 2, 2)))      # 8 x 8 -> 16 x 16 by repeating pixels
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
Xtr = torch.tensor(Xtr, dtype=torch.float32).unsqueeze(1); Xte = torch.tensor(Xte, dtype=torch.float32).unsqueeze(1)
ytr, yte = torch.tensor(ytr), torch.tensor(yte)

class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(1, 16, 3, padding=1); self.bn1 = nn.BatchNorm2d(16)
        self.conv2 = nn.Conv2d(16, 32, 3, padding=1); self.bn2 = nn.BatchNorm2d(32)
        self.fc1 = nn.Linear(32 * 4 * 4, 64); self.fc2 = nn.Linear(64, 10)
    def forward(self, x):
        x = F.max_pool2d(F.relu(self.bn1(self.conv1(x))), 2)           # 16 channels, 8 x 8
        x = F.max_pool2d(F.relu(self.bn2(self.conv2(x))), 2)           # 32 channels, 4 x 4
        return self.fc2(F.relu(self.fc1(x.flatten(1))))

model = SmallCNN()
opt = torch.optim.Adam(model.parameters(), lr=2e-3)
for epoch in range(8):
    model.train(); perm = torch.randperm(len(Xtr))
    for i in range(0, len(Xtr), 64):
        idx = perm[i:i + 64]
        loss = F.cross_entropy(model(Xtr[idx]), ytr[idx])
        opt.zero_grad(); loss.backward(); opt.step()
model.eval()

def accuracy(logits):
    return float((np.asarray(logits).argmax(1) == yte.numpy()).mean())

with torch.inference_mode():
    ref_logits = model(Xte).numpy()                    # the reference answers for every later check
n_params = sum(p.numel() for p in model.parameters())
n_stats = sum(b.numel() for name, b in model.named_buffers() if "running" in name)
macs = 16 * 16 * 16 * (1 * 9) + 8 * 8 * 32 * (16 * 9) + 512 * 64 + 64 * 10   # output values x inputs per output
print(f"train {len(Xtr)} images, test {len(Xte)}; test accuracy (PyTorch, float32): {accuracy(ref_logits):.4f}")
print(f"parameters: {n_params:,} = {4 * n_params:,} bytes in float32, plus {n_stats} BN running statistics")
print(f"multiply-accumulates (MACs) per image: {macs:,}")

def median_us(fns, warmup=50, reps=500):
    # Median time of one call, in microseconds, for each function. The functions are called in turn,
    # so slow drift of the machine (other jobs, frequency changes) affects all of them equally.
    for f in fns.values():
        for _ in range(warmup):
            f()
    times = {k: [] for k in fns}
    for _ in range(reps):
        for k, f in fns.items():
            t0 = time.perf_counter_ns(); f(); times[k].append(time.perf_counter_ns() - t0)
    return {k: float(np.median(v)) / 1e3 for k, v in times.items()}

2. Folding batch normalization into the convolution¶

At inference BN uses fixed running statistics, so for each channel it is just a scale and a shift: $\text{BN}(z) = \gamma\,\frac{z - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta$. A convolution followed by BN is therefore one convolution with new weights and bias. With $s = \gamma / \sqrt{\sigma^2 + \epsilon}$ for each output channel:

$$W' = s\,W, \qquad b' = s\,(b - \mu) + \beta.$$

One layer disappears, and one full pass over the activations with it. We fold both BN layers by hand and check that the outputs agree up to float32 rounding.

def fold_bn(conv, bn):
    s = bn.weight.detach() / torch.sqrt(bn.running_var + bn.eps)          # one scale per output channel
    fused = nn.Conv2d(conv.in_channels, conv.out_channels, conv.kernel_size, conv.stride, conv.padding, bias=True)
    with torch.no_grad():
        fused.weight.copy_(conv.weight * s[:, None, None, None])
        b = conv.bias if conv.bias is not None else torch.zeros_like(bn.running_mean)
        fused.bias.copy_(s * (b - bn.running_mean) + bn.bias)
    return fused

folded = copy.deepcopy(model)
folded.conv1, folded.bn1 = fold_bn(model.conv1, model.bn1), nn.Identity()
folded.conv2, folded.bn2 = fold_bn(model.conv2, model.bn2), nn.Identity()
with torch.inference_mode():
    fold_logits = folded(Xte).numpy()
print(f"largest |difference| in logits, folded vs original: {np.abs(fold_logits - ref_logits).max():.2e}")
print(f"same predicted class on {np.mean(fold_logits.argmax(1) == ref_logits.argmax(1)) * 100:.1f}% of test images; "
      f"accuracy {accuracy(fold_logits):.4f}")
print(f"parameters after folding: {sum(p.numel() for p in folded.parameters()):,} (BN's 96 parameters and 96 statistics are gone)")
x1 = Xte[:1]
with torch.inference_mode():
    t_fold = median_us({"with BN": lambda: model(x1), "folded": lambda: folded(x1)})
print(f"PyTorch, batch 1, one thread: with BN {t_fold['with BN']:.1f} us, folded {t_fold['folded']:.1f} us (median of 500)")

3. Export to ONNX and look inside¶

torch.onnx.export(model, (x,), path, dynamo=True) works in three steps: it captures the model with torch.export (a graph of PyTorch operators, specialized to the example input's shape), translates each operator into ONNX operators, and then optimizes the ONNX graph. Since PyTorch 2.9, dynamo=True is the default. We keep the weights inside the one .onnx file (external_data=False); ONNX files cannot exceed 2 GB, so large models store their weights in a separate data file.

We export the original model, with its BN layers, and look at what came out.

onnx_path = os.path.join(TMP, "cnn.onnx")
torch.onnx.export(model, (x1,), onnx_path, dynamo=True, external_data=False, verbose=False)
onnx_model = onnx.load(onnx_path)
onnx.checker.check_model(onnx_model)                    # structural check: a valid graph of known operators

4. Run with ONNX Runtime and check the answers¶

A converted model is not trusted until its outputs match the original on real inputs. We compare the logits on all 450 test images: the largest absolute difference, and whether the predicted class agrees. Different kernels add numbers in different orders, so float32 results differ by rounding; we compare with a tolerance (here $10^{-4}$), never with ==.

def make_session(path, level=ort.GraphOptimizationLevel.ORT_ENABLE_ALL, threads=1, save_as=None):
    so = ort.SessionOptions()
    so.intra_op_num_threads = threads; so.inter_op_num_threads = 1
    so.graph_optimization_level = level
    so.log_severity_level = 3                            # show errors only
    if save_as:
        so.optimized_model_filepath = save_as            # write the graph as ONNX Runtime rewrote it
    return ort.InferenceSession(path, so, providers=["CPUExecutionProvider"])

def check_conversion(run_one, name, atol=1e-4):
    out = np.concatenate([run_one(Xte[i:i + 1].numpy()) for i in range(len(Xte))])   # one image at a time
    diff = float(np.abs(out - ref_logits).max()); agree = float(np.mean(out.argmax(1) == ref_logits.argmax(1)))
    if atol is None:
        verdict = "quantized: judge by agreement and accuracy"
    else:
        verdict = ("PASS" if diff < atol else "FAIL") + f" at atol {atol:g}"
    print(f"{name:38s} max |diff| {diff:.2e} | top-1 agreement {agree * 100:5.1f}% | accuracy {accuracy(out):.4f} | {verdict}")
    return diff, agree

sess = make_session(onnx_path)
in_name = sess.get_inputs()[0].name
check_conversion(lambda a: sess.run(None, {in_name: a})[0], "ONNX Runtime, float32")
x1_np = x1.numpy()
with torch.inference_mode():
    t_rt = median_us({"PyTorch": lambda: model(x1), "ONNX Runtime": lambda: sess.run(None, {in_name: x1_np})})
for k, v in t_rt.items():
    print(f"batch 1, one thread, {k:12s}: {v:6.1f} us  ->  {macs / v / 1e3:5.2f} GMAC/s effective")

5. Graph optimization levels¶

ONNX Runtime rewrites the graph when it loads a model. Basic does constant folding and removes redundant nodes. Extended adds fusions, such as a convolution and its ReLU into one FusedConv. All adds layout changes: on CPUs such as this one, convolutions switch to the NCHWc layout, which stores channels in blocks that fit the vector registers. This ONNX Runtime version also has a separate Layout level between Extended and All. We save the rewritten graph at each level, list its nodes, and time it.

levels = ["ORT_DISABLE_ALL", "ORT_ENABLE_BASIC", "ORT_ENABLE_EXTENDED"]
levels += ["ORT_ENABLE_LAYOUT"] if hasattr(ort.GraphOptimizationLevel, "ORT_ENABLE_LAYOUT") else []
levels += ["ORT_ENABLE_ALL"]
level_sessions = {}
for lvl in levels:
    saved = os.path.join(TMP, f"optimized_{lvl}.onnx")
    level_sessions[lvl] = make_session(onnx_path, level=getattr(ort.GraphOptimizationLevel, lvl), save_as=saved)
    g = onnx.load(saved).graph
    names = [n.op_type + ("[nchwc]" if "nchwc" in n.domain else "") for n in g.node]
    print(f"{lvl:20s} {len(names):2d} nodes: {' '.join(names)}")
t_lvl = median_us({lvl: (lambda s=s: s.run(None, {in_name: x1_np})) for lvl, s in level_sessions.items()})
for lvl, v in t_lvl.items():
    print(f"{lvl:20s} {v:6.1f} us")

plt.figure(figsize=(8, 3.2))
labels = ["PyTorch"] + [l.replace("ORT_", "").replace("ENABLE_", "").replace("_ALL", " ALL").lower() for l in levels]
vals = [t_rt["PyTorch"]] + [t_lvl[l] for l in levels]
plt.bar(labels, vals, color=["gray"] + ["tab:blue"] * len(levels))
plt.ylabel("median latency (microseconds)"); plt.title("batch 1, one thread, this server CPU: PyTorch vs ONNX Runtime levels", fontsize=10)
plt.tight_layout(); plt.show()

6. Dynamic int8 quantization with ONNX Runtime¶

quantize_dynamic stores the weights as int8 with a scale (session 3), and quantizes the activations on the fly at every call, so it needs no calibration data. We first try it directly on the exported file, then after ONNX Runtime's recommended pre-processing step, quant_pre_process (shape inference and graph clean-up). We quantize either every convolution and matrix product, or only the matrix products (MatMul, Gemm), and compare file size, accuracy, agreement with the float32 model, and latency.

int8_path = os.path.join(TMP, "cnn_int8.onnx")
try:
    quantize_dynamic(onnx_path, int8_path, weight_type=QuantType.QInt8)
    print("direct quantize_dynamic on the exported file: worked")
except Exception as e:
    print(f"direct quantize_dynamic on the exported file failed: {type(e).__name__}: {str(e).splitlines()[0][:100]}")

pre_path = os.path.join(TMP, "cnn_pre.onnx")
quant_pre_process(onnx_path, pre_path)
quantize_dynamic(pre_path, int8_path, weight_type=QuantType.QInt8)                    # Conv, MatMul and Gemm
int8_lin_path = os.path.join(TMP, "cnn_int8_linear_only.onnx")

8. Converting for a phone (NOT RUN here)¶

For Android, the two common routes from PyTorch are LiteRT (formerly TensorFlow Lite), through Google's litert-torch converter (formerly ai-edge-torch), and ExecuTorch, PyTorch's own on-device runtime, whose .pte files are lowered to a backend such as XNNPACK for Arm CPUs. Both start from torch.export, like the ONNX exporter above, and both must be checked against ref_logits on the phone exactly as in section 4. The cell below needs those libraries and a phone connected with adb.

# NOT RUN: needs litert-torch and executorch (pip install litert-torch executorch) and an Android phone with adb
import torch
import litert_torch                                   # Google's PyTorch -> LiteRT converter (formerly ai_edge_torch)
from executorch.exir import to_edge_transform_and_lower
from executorch.backends.xnnpack.partition.xnnpack_partitioner import XnnpackPartitioner

example = (torch.randn(1, 1, 16, 16),)

# LiteRT (formerly TensorFlow Lite): one .tflite file
litert_model = litert_torch.convert(folded.eval(), example)
litert_model.export("cnn.tflite")

# ExecuTorch: torch.export, then hand the supported parts to the XNNPACK CPU backend, then write a .pte file
exported = torch.export.export(folded.eval(), example)
program = to_edge_transform_and_lower(exported, partitioner=[XnnpackPartitioner()]).to_executorch()
with open("cnn.pte", "wb") as f:
    f.write(program.buffer)

What to notice¶

(Written from the saved run. Accuracies, parameter counts and output differences will match yours, and file sizes to within a few bytes. Latencies change from run to run, by up to tens of percent on this shared machine, so read them as rough ratios.)

  1. Folding BN is exact up to rounding. The folded model's logits differed from the original by at most 3.81e-06, every prediction agreed, and accuracy stayed 0.9867. It has 38,282 parameters instead of 38,378. In PyTorch at batch 1 it took 89.8 µs against 111.9 µs, because two fewer operators means less per-operator overhead.
  2. The exporter had already folded BN. The ONNX graph has 10 nodes and no BatchNormalization: the exporter's optimization step folded it. The file is 163,913 bytes, of which 153,144 bytes are stored tensors (38,282 float32 weights plus a 16-byte shape), so the graph description itself costs about 11 kB.
  3. ONNX Runtime gave the same answers. Largest difference 3.81e-06 over all 450 test images, 100% top-1 agreement. At batch 1 it took 23.3 µs against PyTorch's 109.3 µs. The model has only 365,184 MACs, so most of PyTorch's time here is per-operator overhead (Python and dispatch), not arithmetic: 3.34 effective GMAC/s against 15.66. This ratio says little about large models, or about a phone.
  4. Most of the optimization gain came from the layout step. Basic changed nothing (the exporter had already folded the constants). Extended fused Conv + ReLU and Gemm + ReLU (10 nodes became 7) for a small gain, 31.5 µs to 29.2 µs. The Layout and All levels moved the convolutions to the NCHWc layout and took 16.8 µs and 16.5 µs. With these levels, ONNX Runtime warns that a saved model "may contain hardware specific optimizations, and should only be used in the same environment the model was optimized in" (we hid its log messages). So optimize on the target device, or save the model only up to Extended.
  5. Dynamic int8 made the file 3.4 times smaller, but the CNN slower. Quantizing the exported file directly failed with a shape-inference error; after the recommended quant_pre_process step it worked. With all layers in int8: 48,174 bytes instead of 163,913, accuracy still 0.9867, 100% agreement, but 93.2 µs against 17.9 µs for float32. The convolutions became ConvInteger, and every layer quantizes its input again at run time. Quantizing only the linear layers kept the speed (19.7 µs) at 62,839 bytes. This matches ONNX Runtime's advice: dynamic quantization for Transformers and recurrent networks, static quantization (exercise 1) for CNNs. A phone's int8 kernels are different, so measure there before deciding.
  6. The input shape is part of the contract. The batch-1 model rejected a batch of 8 ("Got: 8 Expected: 1"). Re-exported with a symbolic batch dimension, it took all 450 images in one call with the same answers. Batching cut the time per image from 26.9 µs to 6.6 µs, but a phone app answering one user usually runs batch 1.
  7. What runs in between matters. The same float32 session took 23.3 µs when its calls alternated with PyTorch's (section 4), and 16.5–17.9 µs when they alternated with other ONNX Runtime sessions (sections 5 and 6). Session 11 shows how to measure such effects properly.
