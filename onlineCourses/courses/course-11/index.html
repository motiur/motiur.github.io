On-Device AI

Making models small, fast and frugal enough to run offline on phones and microcontrollers, with every technique measured: efficient architectures, quantization, pruning, distillation, ONNX Runtime, memory and the KV cache, small language models and speech on phones, TinyML, honest benchmarking and learning on the device.

  • Pruning
  • Distillation
  • ONNX Runtime
  • TinyML
  • Benchmarking

Sessions

  1. 01

    Why on-device AI, and how to measure cost

    Count the parameters, bytes and multiply–accumulate operations (MACs) of three small models by formula and with forward hooks, measure their single-thread latency against batch size, and place each layer on this CPU's measured roofline to see whether compute or memory limits it.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  2. 02

    Efficient architectures for small devices

    Compute what depthwise separable convolutions save, train a standard CNN and a MobileNet-style CNN on digits, compare their accuracy, size, MACs and single-thread latency in PyTorch and in ONNX Runtime, and sweep the width multiplier to draw an accuracy–MACs–latency trade-off.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  3. 03

    Quantization I: integers instead of floats

    Quantize and dequantize tensors with scales and zero points, measure the error against the number of bits, quantize a trained MLP's weights per tensor and per channel, compare ways to calibrate activation ranges, and run the MLP with integer-only arithmetic in NumPy.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  4. 04

    Quantization II: training-aware and LLM quantization

    Train a small CNN with fake quantization and the straight-through estimator and compare it with post-training quantization at 4, 3 and 2 bits, quantize an LLM-like layer's weights in groups and with NF4, tame activation outliers with SmoothQuant-style scaling, count the true bits per weight, and time a 4-bit weight-only kernel.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  5. 05

    Pruning and sparsity

    Prune an MLP by weight magnitude (one-shot and iterative) and a CNN by whole channels, measure what each sparsity does to accuracy, size and single-thread latency, find where sparse matrix–vector products beat dense ones, and test a lottery-ticket claim with a fair control.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  6. 06

    Knowledge distillation

    Train a small student MLP from a large teacher's softened outputs, compare it with the same student trained directly with all labels and with few labels, sweep the temperature and the loss weight, see what the T² factor does, and quantize the distilled student.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  7. 07

    Model formats and runtimes

    Fold batch normalization into a convolution, export a PyTorch model to ONNX, run and quantize it with ONNX Runtime, and check that the converted model still gives the right answers.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  8. 08

    Memory: weights, activations and the KV cache

    Compute peak memory from tensor lifetimes, reduce it by changing the execution order or by running the first layers patch by patch, and size a language model's KV cache for a phone.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  9. 09

    Small language models and speech on the phone

    Estimate decoding speed from memory bandwidth, measure what a KV cache and int8 quantization change in a small language model, and choose a model and runtime for a phone.

    Read notebook Colab Kaggle .ipynb 2 NOT RUN cells
  10. 10

    TinyML on microcontrollers

    Design a keyword-spotting network that fits a microcontroller's flash and RAM, quantize it to int8, and choose a detection threshold from false accepts per hour on a long audio stream.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  11. 11

    Benchmarking latency and energy honestly

    Build a benchmark harness, measure warm-up, threads, batch size and run-to-run variation, report latency distributions correctly, and estimate energy per inference from stated assumptions.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  12. 12

    Learning on the device, privacy, and the capstone

    Personalize a model on the device from 20 examples by updating all of it, its last layer or only its biases, measure the training memory each needs, and run federated averaging over five simulated phones with compressed updates.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU

Before you start

One notebook per session. Read them with their saved outputs on the course website or on GitHub, or open them in Google Colab or Kaggle Notebooks and run them from the top.

  • Every cell without a NOT RUN label was run once, top to bottom, on a CPU in November 2026 (Python 3.13, PyTorch 2.15, NumPy 2.5, SciPy 1.18, scikit-learn 1.9 and matplotlib 3.11, plus onnx 1.23, onnxscript 0.7 and ONNX Runtime 1.29 in sessions 2, 4, 7 and 11), and the outputs are saved in the notebooks.
  • Sizes in bytes, operation counts and accuracies are exact and reproduce on a second run. Latencies do not: they come from one run on a shared server CPU, often with other jobs running, not from a phone. Treat the printed speed-ups as rough, and measure on your own device (session 11 shows how).
  • The runnable parts use scikit-learn's digits (upsampled to 16 × 16 or 32 × 32 where a session needs bigger images), synthetic keyword audio, or a short text written into the notebook, so each notebook finishes in about a minute on a CPU.
  • On Google Colab or Kaggle, sessions 2, 4, 7 and 11 need pip install onnx onnxscript onnxruntime first; everything else is preinstalled there.
  • Cells marked TODO are exercises for students. Cells marked NOT RUN need a phone, a download or a library that is not installed here (the table below says what each needs). They were written from the tools' documented interfaces and have not been executed, so run each one before recording.
  • Results that went against expectation are stated in each notebook's "What to notice" cell and in the course document. Examples: the depthwise-separable CNN, with 7.2 times fewer operations, was slower than the ordinary CNN in PyTorch at batch 1 but 3.69 times faster in ONNX Runtime (session 2); at 90% sparsity a sparse matrix product was only 2.37 times faster than the dense one (session 5); distillation helped only when labels were scarce (session 6); dynamic int8 quantization made a small CNN's file 3.4 times smaller but about 5 times slower (session 7); patch-based execution cut peak memory 2.12 times but ran about 10 times slower here (session 8); int8 quantization slowed the tiny language model down (session 9); RAM, not flash, limited the microcontroller model (session 10); updating only the biases was the least accurate way to personalize a model (session 12).
