The 2026 paper¶

Amsel, Persson, Musco and Gower, The Polar Express: Optimal Matrix Sign Methods and Their Application to the Muon Algorithm (ICLR 2026, Outstanding Paper Honorable Mention). Muon replaces the update of each weight matrix by its polar factor, computed approximately with a few polynomial iterations. Polar Express chooses the polynomial for each iteration by solving a minimax problem.

This lab is a toy illustration, not a reproduction. We fit our own per-step polynomials with a linear program in float64, so our coefficients differ from the paper's, which also add safeguards for bfloat16 arithmetic. We train a small MLP on the 8×8 digits for 40 steps, not a GPT-2 language model, so the training part can show trends but cannot test the paper's GPT-2 results.

1. The polar factor¶

Write the SVD as $G = U\Sigma V^T$. The polar factor is $Q = UV^T$: the same singular vectors, with every singular value set to 1. Then $G = QH$ with $H = V\Sigma V^T$ symmetric and positive semi-definite. $Q$ is also the matrix with orthonormal columns closest to $G$, which is why Muon uses it as an update direction.

import time
import numpy as np
import matplotlib.pyplot as plt
from scipy.optimize import linprog

np.random.seed(0)
rng = np.random.default_rng(0)
m, n = 64, 32
U, _ = np.linalg.qr(rng.standard_normal((m, n)))      # 64 x 32, orthonormal columns
V, _ = np.linalg.qr(rng.standard_normal((n, n)))      # 32 x 32, orthogonal
s = np.logspace(0, -3, n)                              # singular values from 1 down to 0.001
G = U @ np.diag(s) @ V.T                               # a "gradient" whose singular values are badly spread

Us, ss, Vts = np.linalg.svd(G, full_matrices=False)
Q = Us @ Vts                                           # polar factor
H = Vts.T @ np.diag(ss) @ Vts                          # G = Q H
print(f"||Q^T Q - I|| = {np.linalg.norm(Q.T @ Q - np.eye(n)):.1e}    ||Q H - G|| = {np.linalg.norm(Q @ H - G):.1e}")
print(f"H symmetric: {np.allclose(H, H.T)}    smallest eigenvalue of H: {np.linalg.eigvalsh(H).min():.2e}")

# Q is the closest matrix with orthonormal columns: compare with 2,000 orthonormal matrices near Q.
def polar(M):
    u, _, vt = np.linalg.svd(M, full_matrices=False)
    return u @ vt
near = [np.linalg.norm(G - polar(Q + 0.05 * rng.standard_normal((m, n)))) for _ in range(2000)]
print(f"distance from G to Q: {np.linalg.norm(G - Q):.4f}    closest of 2,000 nearby orthonormal matrices: {min(near):.4f}")

2. Polynomials act on singular values¶

For an odd polynomial $p(x) = ax + bx^3 + cx^5$, define $p(X) = aX + bX(X^TX) + cX(X^TX)^2$. Because $X^TX = V\Sigma^2V^T$, this equals $U\,p(\Sigma)\,V^T$: the matrix keeps its singular vectors and each singular value $\sigma$ becomes $p(\sigma)$. So we only need a polynomial that sends every singular value to 1, and we never need an SVD, a QR or an inverse, only matrix products, which GPUs run fast and in low precision.

def apply_odd_poly(X, coef):
    # p(X) = a X + b X (X^T X) [+ c X (X^T X)^2] for coef = (a, b) or (a, b, c): matrix products only
    A = X.T @ X                                    # small n x n Gram matrix
    if len(coef) == 2:
        a, b = coef
        return a * X + b * (X @ A)
    a, b, c = coef
    return a * X + X @ (b * A + c * (A @ A))

coef = (1.5, -0.5)
lhs = np.linalg.svd(apply_odd_poly(G, coef), compute_uv=False)
rhs = np.sort(coef[0] * s + coef[1] * s**3)[::-1]
print(f"largest gap between the singular values of p(G) and p(singular values of G): {np.abs(lhs - rhs).max():.1e}")

3. Three iterations¶

  1. Cubic Newton–Schulz, $p(x) = 1.5x - 0.5x^3$. It converges to 1 for singular values in $(0, \sqrt{3})$, but a tiny singular value only grows by a factor of about 1.5 per step.
  2. Muon's fixed quintic (Jordan et al. 2024), $p(x) = 3.4445x - 4.7750x^3 + 2.0315x^5$. Its slope at 0 is 3.4445, so small singular values grow fast, but $p(1) = 0.701$, so it never converges exactly: it leaves the singular values in a band around 1.
  3. A per-step minimax quintic (our version of the Polar Express idea). If the singular values lie in $[\ell, u]$, choose $p$ to minimize the worst error $\max_{x \in [\ell, u]} |1 - p(x)|$. The new singular values then lie in $[\min p, \max p]$, and we repeat on that interval. We solve each minimax problem as a linear program on 3,000 grid points. The paper solves it exactly and proves this greedy choice is optimal. When the interval becomes tiny, our linear program becomes ill-conditioned, so we switch to the classical quintic $(15x - 10x^3 + 3x^5)/8$, which has $p(1) = 1$ and $p'(1) = p''(1) = 0$.
NS3 = (1.5, -0.5)                      # cubic Newton-Schulz
JORDAN5 = (3.4445, -4.7750, 2.0315)    # fixed quintic used in Muon (Jordan et al. 2024)
NS5 = (15 / 8, -10 / 8, 3 / 8)         # classical quintic, for the final steps

def poly(coef, x):
    return sum(c * x ** (2 * i + 1) for i, c in enumerate(coef))

def minimax_quintic(lo, hi, n_grid=3000):
    # odd quintic that minimizes max |1 - p(x)| over [lo, hi], by linear programming on a grid
    x = np.unique(np.concatenate([np.geomspace(lo, hi, n_grid // 2), np.linspace(lo, hi, n_grid // 2)]))
    Phi = np.stack([x, x**3, x**5], axis=1)
    one = np.ones((len(x), 1))
    # unknowns (a, b, c, E): minimize E subject to -E <= 1 - p(x_i) <= E at every grid point
    res = linprog(c=[0, 0, 0, 1], A_ub=np.block([[-Phi, -one], [Phi, -one]]),
                  b_ub=np.concatenate([-np.ones(len(x)), np.ones(len(x))]),
                  bounds=[(None, None)] * 4, method="highs")
    return tuple(res.x[:3])

def minimax_schedule(lo=1e-3, hi=1.0, steps=8):
    sched = []
    for k in range(steps):
        coef = NS5 if hi - lo < 1e-2 else minimax_quintic(lo, hi)
        x = np.linspace(lo, hi, 4001)
        lo, hi = poly(coef, x).min(), poly(coef, x).max()          # where the singular values are now
        sched.append(coef)
        print(f"step {k + 1}: p(x) = {coef[0]:7.4f} x {coef[1]:+9.4f} x^3 {coef[2]:+9.4f} x^5   "
              f"singular values now in [{lo:.6f}, {hi:.6f}]")
    return sched

MINIMAX = minimax_schedule(lo=1e-3)       # designed for singular values in [0.001, 1]

4. Orthogonality error per iteration¶

Muon first divides the matrix by its Frobenius norm, which puts every singular value at or below 1. We then apply each iteration and measure the spectral-norm distance to the true polar factor $Q$. This distance is $\max_i |1 - p_k(\sigma_i)|$, so it is set by the singular value that is furthest from 1.

X0 = G / np.linalg.norm(G)

5. Muon from scratch¶

For each 2-D hidden weight matrix: keep a momentum buffer, form a Nesterov-style update $u = g + \mu \cdot \text{buffer}$, replace $u$ by its approximate polar factor, scale by $\sqrt{\max(1, \text{rows}/\text{cols})}$ as in the Muon reference code, and step. Biases and the output layer use AdamW, as Muon's authors recommend. Only the orthogonalization method changes between runs.

import torch
import torch.nn as nn
import torch.nn.functional as F
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

torch.set_num_threads(2)                      # small matrices: two threads are enough
COEFS = {"cubic NS": [NS3] * 8, "Muon quintic": [JORDAN5] * 8, "minimax (ours)": MINIMAX}

def orthogonalize(M, method, steps=5):
    if method == "exact SVD":
        u, _, vh = torch.linalg.svd(M, full_matrices=False)
        return u @ vh
    X = M / (M.norm() + 1e-7)
    transposed = X.shape[0] < X.shape[1]       # make X tall so that X^T X is the smaller Gram matrix
    if transposed:
        X = X.T
    for coef in COEFS[method][:steps]:
        X = apply_odd_poly(X, coef)            # the function from section 2 works on torch tensors too
    return X.T if transposed else X

class Muon(torch.optim.Optimizer):
    def __init__(self, params, lr=0.05, momentum=0.95, method="Muon quintic", steps=5):
        super().__init__(params, dict(lr=lr, momentum=momentum, method=method, steps=steps))

    @torch.no_grad()
    def step(self):
        for group in self.param_groups:
            for p in group["params"]:
                buf = self.state[p].setdefault("buf", torch.zeros_like(p))
                buf.mul_(group["momentum"]).add_(p.grad)
                u = p.grad + group["momentum"] * buf
                o = orthogonalize(u, group["method"], group["steps"])
                p.add_(o, alpha=-group["lr"] * max(1, p.shape[0] / p.shape[1]) ** 0.5)

# check: 5 quintic steps on a random 128 x 64 matrix, singular values of the result
torch.manual_seed(0)
sv = torch.linalg.svdvals(orthogonalize(torch.randn(128, 64), "Muon quintic"))
print(f"Muon quintic, 5 steps: singular values of the update in [{sv.min():.3f}, {sv.max():.3f}]")

6. Training at a fixed budget, across learning rates¶

A 64-128-128-10 MLP on the 8×8 digits (1,347 training and 450 test images), 40 steps with batches of 64, five seeds per setting. The paper compares methods across a range of learning rates, so we do the same: a method is only better if its best learning rate gives a lower loss. The paper's experiments train GPT-2 language models on GPUs.

digits = load_digits()
X_all = torch.tensor(digits.data / 16.0, dtype=torch.float32)
y_all = torch.tensor(digits.target)
Xtr, Xte, ytr, yte = train_test_split(X_all, y_all, test_size=0.25, random_state=0, stratify=y_all)

def make_model(seed):
    torch.manual_seed(seed)
    return nn.Sequential(nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, 128), nn.ReLU(), nn.Linear(128, 10))

def train(method, lr, seed, steps=40, n_iter=5, batch=64):
    model = make_model(seed)
    hidden = [model[0].weight, model[2].weight]
    rest = [model[0].bias, model[2].bias, model[4].weight, model[4].bias]
    if method == "AdamW":
        opts = [torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=0.0)]
    else:
        opts = [Muon(hidden, lr=lr, method=method, steps=n_iter), torch.optim.AdamW(rest, lr=3e-3, weight_decay=0.0)]
    gen = torch.Generator().manual_seed(seed)
    for _ in range(steps):
        idx = torch.randint(0, len(Xtr), (batch,), generator=gen)
        loss = F.cross_entropy(model(Xtr[idx]), ytr[idx])
        for o in opts:
            o.zero_grad()
        loss.backward()
        for o in opts:
            o.step()
    with torch.no_grad():
        return F.cross_entropy(model(Xtr), ytr).item(), (model(Xte).argmax(1) == yte).float().mean().item()

grid.update({m_: [0.02, 0.05, 0.1, 0.2] for m_ in ["cubic NS", "Muon quintic", "minimax (ours)", "exact SVD"]})

8. Timing on a GPU (NOT RUN here)¶

Polar Express is about speed on GPUs. On a GPU, compare five quintic steps in bfloat16 with an SVD in float32 for a large matrix.

# NOT RUN: needs a CUDA GPU (the point is how matrix products compare with an SVD on GPU hardware)
import time, torch
G = torch.randn(4096, 4096, device="cuda")
def five_steps(G, coef=(3.4445, -4.7750, 2.0315)):
    X = (G / G.norm()).bfloat16()
    for _ in range(5):
        A = X.T @ X
        X = coef[0] * X + X @ (coef[1] * A + coef[2] * (A @ A))
    return X
for name, f in [("5 quintic steps, bfloat16", lambda: five_steps(G)), ("SVD, float32", lambda: torch.linalg.svd(G))]:
    f(); torch.cuda.synchronize(); t0 = time.time()
    for _ in range(10): f()
    torch.cuda.synchronize(); print(f"{name:28s} {(time.time() - t0) / 10 * 1000:.1f} ms")

What to notice¶

  • Matrix products are enough. After 9 iterations our minimax schedule matched the SVD polar factor to about 5e-14, with no SVD, QR or inverse.
  • Early speed differs a lot. On a matrix with singular values from 0.0006 to 0.6, the error after 5 iterations was still about 1.0 for cubic Newton–Schulz (a small singular value grows only about 1.5 times per step), 0.71 for Muon's fixed quintic and 0.41 for our minimax schedule.
  • Muon's quintic is inexact on purpose. Its error stopped at 0.32 from iteration 6 on, and 5 steps sent singular values from [0.001, 1] anywhere in [0.47, 1.20]. Muon accepts this in exchange for fast growth of small singular values.
  • The lower bound matters. Our schedule was designed for singular values of at least 0.001. This matrix had one at 0.0006, so after 5 iterations the error was 0.41, not the 0.11 that the design interval promises.
  • In training, extra accuracy stopped paying off quickly. At the best learning rate (0.1 for every Muon variant), the training loss after 40 steps was 0.168 for cubic Newton–Schulz but 0.089 for Muon's quintic, 0.092 for our minimax schedule and 0.089 for the exact SVD; the last three are well within one standard deviation of each other over 5 seeds. AdamW's best was 0.180. More than 3 (minimax) or 5 (quintic) iterations did not lower the loss.
  • Against expectation: the exact polar factor did no better than five quintic steps, and our minimax schedule did not beat the quintic. A 40-step MLP on 8×8 digits cannot test the paper's GPT-2 result. It only shows that a better matrix approximation need not give a better optimizer.
