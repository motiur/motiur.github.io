1. Setup¶

Everything here is small: 8×8 digits for the image models and 2-D point clouds for the flow and the GANs. Real models are thousands of times bigger, but the ideas and the failure modes are the same. Small models run fastest on one CPU thread, so we set that.

2. A VAE with a 2-D latent space¶

The encoder outputs a mean and a log-variance for $q(z \mid x)$; the decoder outputs one Bernoulli probability per pixel. We binarize the pixels (on if above half intensity) so that each pixel really is a 0/1 variable; then the ELBO is an exact lower bound on $\log p(x)$, in nats:

$\log p(x) \ge \mathbb{E}_{q(z|x)}[\log p(x \mid z)] - \mathrm{KL}(q(z \mid x) \,\|\, N(0, I))$

The reparameterization trick writes $z = \mu + \sigma \cdot \varepsilon$ with $\varepsilon \sim N(0, I)$, so the sampling step has a gradient with respect to $\mu$ and $\sigma$.

Btr = torch.tensor(Xtr > 0.5, dtype=torch.float32); Bte = torch.tensor(Xte > 0.5, dtype=torch.float32)

class VAE(nn.Module):
    def __init__(self, z_dim=2, h=256):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(64, h), nn.ReLU(), nn.Linear(h, h), nn.ReLU(), nn.Linear(h, 2 * z_dim))
        self.dec = nn.Sequential(nn.Linear(z_dim, h), nn.ReLU(), nn.Linear(h, h), nn.ReLU(), nn.Linear(h, 64))
    def forward(self, x):
        mu, logvar = self.enc(x).chunk(2, dim=1)
        z = mu + torch.exp(0.5 * logvar) * torch.randn_like(mu)          # reparameterization trick
        return self.dec(z), mu, logvar

def elbo_terms(model, x):
    logits, mu, logvar = model(x)
    rec = F.binary_cross_entropy_with_logits(logits, x, reduction="none").sum(1)   # -log p(x|z), nats per image
    kl = 0.5 * (mu ** 2 + logvar.exp() - 1 - logvar).sum(1)                       # KL(q(z|x) || N(0, I)), closed form
    return rec.mean(), kl.mean()

t0 = time.time(); torch.manual_seed(0)
vae = VAE(); opt = torch.optim.Adam(vae.parameters(), lr=1e-3)
for epoch in range(100):
    for idx in torch.randperm(len(Btr)).split(128):
        rec, kl = elbo_terms(vae, Btr[idx]); loss = rec + kl              # loss = negative ELBO
        opt.zero_grad(); loss.backward(); opt.step()
with torch.no_grad():
    torch.manual_seed(1); rec, kl = elbo_terms(vae, Bte)
print(f"VAE trained in {time.time() - t0:.0f}s")
print(f"test reconstruction term {rec.item():.2f} nats, KL term {kl.item():.2f} nats, negative ELBO {rec.item() + kl.item():.2f} nats per image")

How loose is the bound? An importance-sampling estimate of $\log p(x)$ draws $K$ samples from the encoder and averages $p(x \mid z)\,p(z)/q(z \mid x)$. As $K$ grows it approaches the true $\log p(x)$ from below, so it is tighter than the ELBO. The gap between the two is $\mathrm{KL}(q(z \mid x) \,\|\, p(z \mid x))$: how far the encoder is from the true posterior.

@torch.no_grad()
def log_px_estimate(model, x, K=500):
    mu, logvar = model.enc(x).chunk(2, dim=1); std = torch.exp(0.5 * logvar)
    z = mu + std * torch.randn(K, *mu.shape)                              # K samples per image from q(z|x)
    log_px_z = -F.binary_cross_entropy_with_logits(model.dec(z), x.expand(K, -1, -1), reduction="none").sum(-1)
    log_pz = (-0.5 * z ** 2 - 0.5 * math.log(2 * math.pi)).sum(-1)
    log_qz = (-0.5 * ((z - mu) / std) ** 2 - torch.log(std) - 0.5 * math.log(2 * math.pi)).sum(-1)
    return (torch.logsumexp(log_px_z + log_pz - log_qz, dim=0) - math.log(K)).mean().item()

torch.manual_seed(2)
nll_is = -log_px_estimate(vae, Bte)
print(f"test -log p(x), importance sampling with K=500: {nll_is:.2f} nats per image")
print(f"test negative ELBO:                             {rec.item() + kl.item():.2f} nats per image  (an upper bound on -log p(x))")

3. A VQ-VAE: images become tokens¶

The encoder turns each 8×8 digit into a 4×4 grid of 8-dimensional vectors. Each vector is replaced by its nearest entry in a codebook of $K = 32$ vectors, so an image becomes 16 integers (tokens). Three loss terms (van den Oord et al. 2017):

loss = reconstruction + ||sg[z_e] - e||^2 + 0.25 * ||z_e - sg[e]||^2

where sg means stop-gradient (.detach()). The second term moves the codebook vectors toward the encoder outputs; the third (the commitment loss) keeps the encoder close to its chosen codes. The nearest-code lookup has no useful gradient, so the straight-through trick copies the decoder's gradient from z_q to z_e.

Itr = torch.tensor(Xtr, dtype=torch.float32).view(-1, 1, 8, 8); Ite = torch.tensor(Xte, dtype=torch.float32).view(-1, 1, 8, 8)

class VQVAE(nn.Module):
    def __init__(self, K=32, D=8):
        super().__init__()
        self.enc = nn.Sequential(nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), nn.Conv2d(32, 32, 4, stride=2, padding=1), nn.ReLU(), nn.Conv2d(32, D, 1))
        self.codebook = nn.Embedding(K, D); self.codebook.weight.data.uniform_(-1 / K, 1 / K)
        self.dec = nn.Sequential(nn.Conv2d(D, 32, 3, padding=1), nn.ReLU(), nn.ConvTranspose2d(32, 32, 4, stride=2, padding=1), nn.ReLU(), nn.Conv2d(32, 1, 3, padding=1))
    def quantize(self, ze):                                           # ze: (B, D, 4, 4)
        B, D, H, W = ze.shape
        flat = ze.permute(0, 2, 3, 1).reshape(-1, D)
        idx = torch.cdist(flat, self.codebook.weight).argmin(1)          # nearest codebook vector: an integer
        zq = self.codebook(idx).view(B, H, W, D).permute(0, 3, 1, 2)
        return zq, idx.view(B, H, W)
    def forward(self, x):
        ze = self.enc(x); zq, idx = self.quantize(ze)
        zq_st = ze + (zq - ze).detach()                                  # straight-through: value of zq, gradient of ze
        return self.dec(zq_st), ze, zq, idx

t0 = time.time(); torch.manual_seed(0)
vq = VQVAE(); opt = torch.optim.Adam(vq.parameters(), lr=2e-3)
for epoch in range(60):
    for idx in torch.randperm(len(Itr)).split(128):
        x = Itr[idx]; xr, ze, zq, _ = vq(x)
        loss = F.mse_loss(xr, x) + F.mse_loss(zq, ze.detach()) + 0.25 * F.mse_loss(ze, zq.detach())
        opt.zero_grad(); loss.backward(); opt.step()

perplexity = torch.exp(-(p[p > 0] * p[p > 0].log()).sum()).item()

print(f"each image is now 16 tokens of 5 bits = 80 bits. The first test digit (a {yte[0]}) as tokens:")
print(codes[0].numpy())

4. A coupling flow on two moons: exact likelihood¶

A RealNVP-style coupling layer (Dinh et al. 2017) keeps one coordinate and transforms the other: $y_b = x_b \cdot e^{s(x_a)} + t(x_a)$. The Jacobian is triangular, so $\log|\det J| = s(x_a)$, and the inverse is $x_b = (y_b - t(y_a)) e^{-s(y_a)}$. Stacking 8 layers that alternate the kept coordinate gives a flexible invertible map $z = f(x)$, trained by maximizing the exact log-likelihood

$\log p(x) = \log N(f(x); 0, I) + \log |\det \partial f / \partial x|$.

We standardize the data, so likelihoods are in nats per point in standardized units. The baseline is a single Gaussian fitted to the training data.

Xm, _ = make_moons(3000, noise=0.05, random_state=0)
Xm = (Xm - Xm.mean(0)) / Xm.std(0)
Mtr, Mte = torch.tensor(Xm[:2000], dtype=torch.float32), torch.tensor(Xm[2000:], dtype=torch.float32)

class Coupling(nn.Module):
    def __init__(self, flip, h=64):
        super().__init__(); self.flip = flip
        self.net = nn.Sequential(nn.Linear(1, h), nn.ReLU(), nn.Linear(h, h), nn.ReLU(), nn.Linear(h, 2))
    def split(self, x): return (x[:, 1:], x[:, :1]) if self.flip else (x[:, :1], x[:, 1:])
    def join(self, a, b): return torch.cat([b, a], 1) if self.flip else torch.cat([a, b], 1)
    def forward(self, x):                                   # x -> y, and log|det J| of this layer
        a, b = self.split(x); s, t = self.net(a).chunk(2, dim=1); s = torch.tanh(s)     # tanh keeps the scale bounded
        return self.join(a, b * torch.exp(s) + t), s.sum(1)
    def inverse(self, y):
        a, b = self.split(y); s, t = self.net(a).chunk(2, dim=1); s = torch.tanh(s)
        return self.join(a, (b - t) * torch.exp(-s))

class Flow(nn.Module):
    def __init__(self, n_layers=8):
        super().__init__(); self.layers = nn.ModuleList([Coupling(flip=i % 2 == 1) for i in range(n_layers)])
    def forward(self, x):
        logdet = torch.zeros(len(x))
        for layer in self.layers: x, ld = layer(x); logdet = logdet + ld
        return x, logdet
    def log_prob(self, x):
        z, logdet = self(x)
        return (-0.5 * z ** 2 - 0.5 * math.log(2 * math.pi)).sum(1) + logdet
    def inverse(self, z):
        for layer in reversed(self.layers): z = layer.inverse(z)
        return z

5. GANs on a ring of eight Gaussians: mode dropping, and one fix¶

The data are eight tight clusters on a circle. We count a mode as covered if at least 1% of 2,000 generated points land within 3 standard deviations of its centre, and report the share of points that land near any mode (a simple precision).

A vanilla GAN needs a careful balance between its two players. Here the discriminator learns four times faster than the generator (learning rates 0.001 and 0.00025), a setting where that balance matters. We compare two models in exactly this setting:

  • Vanilla GAN (Goodfellow et al. 2014) with the non-saturating generator loss.
  • WGAN-GP: a Wasserstein critic (Arjovsky et al. 2017) whose Lipschitz constraint is enforced by a gradient penalty (Gulrajani et al. 2017) instead of weight clipping. A Wasserstein critic should give the generator useful gradients even when the critic is well trained. The paper's defaults are a penalty weight of 10 and five critic steps per generator step; for this 2-D toy problem we use 0.1 and two steps to fit the time budget.

Three seeds each, the same networks and 2,000 generator steps. The lists show the number of modes covered every 250 steps.

CENTERS = np.stack([2 * np.cos(2 * np.pi * np.arange(8) / 8), 2 * np.sin(2 * np.pi * np.arange(8) / 8)], 1)
STD = 0.02
def ring(n, rng): return (CENTERS[rng.integers(0, 8, n)] + STD * rng.standard_normal((n, 2))).astype(np.float32)
def mode_stats(x):
    d = np.linalg.norm(x[:, None] - CENTERS[None], axis=2); near = d.min(1) < 3 * STD
    counts = np.bincount(d.argmin(1)[near], minlength=8)
    return int((counts >= 0.01 * len(x)).sum()), near.mean()

def G(): return nn.Sequential(nn.Linear(2, 128), nn.ReLU(), nn.Linear(128, 128), nn.ReLU(), nn.Linear(128, 2))
def D(): return nn.Sequential(nn.Linear(2, 128), nn.ReLU(), nn.Linear(128, 128), nn.ReLU(), nn.Linear(128, 1))

def train_gan(kind, seed, steps=2000, B=128, lr_g=2.5e-4, lr_d=1e-3):
    torch.manual_seed(seed); rng = np.random.default_rng(seed); g, d = G(), D()
    betas = (0.5, 0.9) if kind == "wgan-gp" else (0.5, 0.999)
    og, od = torch.optim.Adam(g.parameters(), lr_g, betas=betas), torch.optim.Adam(d.parameters(), lr_d, betas=betas)
    history = []
    for step in range(steps):
        for _ in range(2 if kind == "wgan-gp" else 1):                     # critic / discriminator steps
            real, fake = torch.from_numpy(ring(B, rng)), g(torch.randn(B, 2)).detach()
            if kind == "wgan-gp":
                e = torch.rand(B, 1); xi = (e * real + (1 - e) * fake).requires_grad_(True)
                grad, = torch.autograd.grad(d(xi).sum(), xi, create_graph=True)
                ld = d(fake).mean() - d(real).mean() + 0.1 * ((grad.norm(dim=1) - 1) ** 2).mean()
            else:
                ld = F.softplus(-d(real)).mean() + F.softplus(d(fake)).mean()   # -log D(real) - log(1 - D(fake))
            od.zero_grad(); ld.backward(); od.step()
        out = d(g(torch.randn(B, 2)))
        lg = -out.mean() if kind == "wgan-gp" else F.softplus(-out).mean()     # vanilla: -log D(G(z))
        og.zero_grad(); lg.backward(); og.step()
        if (step + 1) % 250 == 0:
            with torch.no_grad(): history.append(mode_stats(g(torch.randn(1000, 2)).numpy())[0])
    with torch.no_grad(): return g(torch.randn(2000, 2)).numpy(), history

t0 = time.time(); gan_samples = {}
for kind in ["vanilla", "wgan-gp"]:
    for seed in [0, 1, 2]:
        x, hist = train_gan(kind, seed); gan_samples[kind, seed] = x; m, near = mode_stats(x)
        print(f"{kind:8s} seed {seed}: modes covered {m}/8, share of points near a mode {near:.2f}, modes during training {hist}")
print(f"six GANs trained in {time.time() - t0:.0f}s")

6. Measuring samples: Fréchet distance, precision and recall¶

The Fréchet distance fits a Gaussian to each set and compares them: $\|\mu_r - \mu_g\|^2 + \mathrm{Tr}(\Sigma_r + \Sigma_g - 2(\Sigma_r \Sigma_g)^{1/2})$. FID (Heusel et al. 2017) is this distance computed on Inception-network features of images; here we use the 2-D points directly.

Precision and recall (Kynkäänniemi et al. 2019) estimate each set's support with k-nearest-neighbour balls (k = 3): precision is the share of generated points inside the real support, recall the share of real points inside the generated support.

Two extra rows help you read the measures: perfect points from one mode only (a fully collapsed generator), and a trap, one Gaussian with the same mean and covariance as the ring. The modes column is the mode count from section 5; we can only compute it because we know where the true modes are, which is never the case for real images.

def frechet(a, b):
    mu_a, mu_b, Ca, Cb = a.mean(0), b.mean(0), np.cov(a.T), np.cov(b.T)
    covmean = linalg.sqrtm(Ca @ Cb).real
    return float(((mu_a - mu_b) ** 2).sum() + np.trace(Ca + Cb - 2 * covmean))

def precision_recall(real, fake, k=3):
    def radii(x):
        d = np.linalg.norm(x[:, None] - x[None], axis=2); return np.sort(d, axis=1)[:, k]     # column 0 is the point itself
    d_fr = np.linalg.norm(fake[:, None] - real[None], axis=2)
    precision = (d_fr <= radii(real)[None]).any(1).mean()
    recall = (d_fr.T <= radii(fake)[None]).any(1).mean()
    return precision, recall

rng = np.random.default_rng(10); real_ref, real_other = ring(2000, rng), ring(2000, rng)
blob = rng.multivariate_normal(real_ref.mean(0), np.cov(real_ref.T), 2000)

What to notice¶

(Written from the run above; your numbers will match if you keep the seeds.)

  1. The ELBO really is a bound. On binarized test digits the negative ELBO was 20.20 nats per image and the importance-sampled estimate of −log p(x) was 19.51 nats, lower as a bound requires. The gap of about 0.7 nats is the KL divergence from the encoder to the true posterior.
  2. The VAE organized its 2-D latent space by digit class without seeing labels, but its decoded images are blurry averages.
  3. The VQ-VAE turned each digit into 16 tokens (80 bits) with a test MSE of 0.0069. All 32 codes were used (perplexity 26.3), so this small codebook had no unused ("dead") codes; the assignment asks whether that stays true for larger codebooks.
  4. The flow gave an exact likelihood: −1.226 nats per test point against −2.732 for one Gaussian. Inverting it recovered the inputs to within 1.8e-06, and its log-determinant matched autograd.
  5. GANs, with the discriminator learning four times faster: the vanilla GAN covered 4 of 8 modes in all three seeds, with about 60% of its points near a mode. WGAN-GP covered 7, 8 and 8 modes, and its coverage rose steadily during training, but only 31–40% of its points were near a mode. So in this run the fix bought recall (coverage) and paid in precision; neither model had converged after 2,000 steps. Both draw a connected ring: a continuous generator fed with connected 2-D noise cannot make eight separate islands, so some points always fall between modes.
  6. Metrics can mislead. The fully collapsed set had precision 0.97 and recall 0.12, the textbook signature of mode collapse. But the vanilla GAN, with 4 of 8 modes, still scored recall 0.91: its scattered points have large neighbourhood balls that cover the missing modes, so k-NN recall is sensitive to outliers. And one Gaussian blob, which looks nothing like the ring, got a Fréchet distance of 0.004, better than both GANs (0.010 and 0.006), with precision 0.00. The Fréchet distance only compares means and covariances.
  7. Sample size changes the Fréchet distance: two real samples of the same ring gave 0.2123 at 50 points and 0.0017 at 5,000.
  8. Everything here is toy-scale: a few thousand 2-D points or 8×8 images. The failure modes (blur, mode dropping, misleading metrics) are the ones you meet at full scale, but the sizes of the effects are not.
