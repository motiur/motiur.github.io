1. Three ways to get a derivative¶

We use the running example of Baydin et al. (2018): $f(x_1, x_2) = \ln x_1 + x_1 x_2 - \sin x_2$ at $(x_1, x_2) = (2, 5)$.

  • Symbolic (by hand, or by a computer-algebra system): $\partial f/\partial x_1 = 1/x_1 + x_2$ and $\partial f/\partial x_2 = x_1 - \cos x_2$. Exact, but for long programs the expressions can grow very large.
  • Numerical: central differences (session 4). Easy, but approximate, and it needs two evaluations of $f$ per input.
  • Automatic (AD): run the program and apply the chain rule to each elementary operation as it happens. Exact up to rounding, at the cost of a few evaluations of $f$.

A program is a sequence of elementary operations, an evaluation trace, which we can draw as a computational graph. By hand first: compute $f(2, 5)$ and both partial derivatives ($\cos 5 \approx 0.2837$, $\sin 5 \approx -0.9589$).

2. Forward mode with dual numbers¶

A dual number $a + b\varepsilon$ uses a new symbol with $\varepsilon^2 = 0$. Then $f(a + b\varepsilon) = f(a) + f'(a)\,b\,\varepsilon$: the value and the derivative travel together through the program. For example $(a + b\varepsilon)(c + d\varepsilon) = ac + (ad + bc)\varepsilon$, which is the product rule. To get $\partial f/\partial x_1$, give $x_1$ the tangent $b = 1$ and every other input $b = 0$; that is one forward pass per input.

By hand first: expand $(2 + \varepsilon)^3$ using $\varepsilon^2 = 0$. The coefficient of $\varepsilon$ is the derivative of $x^3$ at 2.

COUNT = {"ops": 0}          # counts elementary operations, for section 4

class Dual:
    # a + b*eps with eps^2 = 0: a is the value, b the derivative (the "tangent")
    def __init__(self, a, b=0.0):
        self.a, self.b = float(a), float(b)
    @staticmethod
    def lift(o):
        return o if isinstance(o, Dual) else Dual(o)
    def __add__(self, o):
        o = Dual.lift(o); COUNT["ops"] += 1
        return Dual(self.a + o.a, self.b + o.b)
    def __sub__(self, o):
        o = Dual.lift(o); COUNT["ops"] += 1
        return Dual(self.a - o.a, self.b - o.b)
    def __mul__(self, o):
        o = Dual.lift(o); COUNT["ops"] += 1
        return Dual(self.a * o.a, self.a * o.b + self.b * o.a)          # product rule
    def __truediv__(self, o):
        o = Dual.lift(o); COUNT["ops"] += 1
        return Dual(self.a / o.a, (self.b * o.a - self.a * o.b) / o.a ** 2)
    def __pow__(self, k):                                               # k is a plain number
        COUNT["ops"] += 1
        return Dual(self.a ** k, k * self.a ** (k - 1) * self.b)
    __radd__, __rmul__ = __add__, __mul__
    def __rsub__(self, o): return Dual.lift(o) - self
    def __neg__(self): return self * -1.0
    def sin(self):  COUNT["ops"] += 1; return Dual(math.sin(self.a), math.cos(self.a) * self.b)
    def log(self):  COUNT["ops"] += 1; return Dual(math.log(self.a), self.b / self.a)
    def exp(self):  COUNT["ops"] += 1; e = math.exp(self.a); return Dual(e, e * self.b)
    def tanh(self): COUNT["ops"] += 1; t = math.tanh(self.a); return Dual(t, (1 - t * t) * self.b)
    def __repr__(self): return f"Dual({self.a:.6g}, {self.b:.6g})"

3. Reverse mode: one backward pass gives every partial derivative¶

Reverse mode first runs the program forward and records the trace. Then it walks the trace backwards and computes the adjoint $\bar v = \partial f / \partial v$ of every intermediate value with the chain rule: if $v$ feeds into $w_1, w_2, \dots$, then $\bar v = \sum_k \bar w_k \, \partial w_k / \partial v$.

By hand first, on the trace of section 1: start with $\bar v_7 = 1$. Then $\bar v_6 = 1$, $\bar v_5 = -1$, $\bar v_3 = \bar v_4 = 1$, and

  • $\bar v_2 = \bar v_4 \cdot v_1 + \bar v_5 \cdot \cos v_2 = 2 - \cos 5$,
  • $\bar v_1 = \bar v_3 \cdot (1 / v_1) + \bar v_4 \cdot v_2 = 0.5 + 5$.

Both partial derivatives come out of a single backward pass. A second check by hand: for $g(x, y) = xy + x^2$ at $(3, 2)$, find $\partial g/\partial x$ and $\partial g/\partial y$.

The class below is a small scalar reverse-mode engine in the style of Karpathy's micrograd. Course 1 session 5 builds a similar one step by step; here we use it to compare the two modes.

class Value:
    # a scalar that remembers its parents and how to send a gradient back to them (reverse mode)
    def __init__(self, data, parents=()):
        self.data, self.grad = float(data), 0.0
        self._parents, self._backward = parents, None
    @staticmethod
    def lift(o):
        return o if isinstance(o, Value) else Value(o)
    def __add__(self, o):
        o = Value.lift(o); out = Value(self.data + o.data, (self, o)); COUNT["ops"] += 1
        def _backward():
            self.grad += out.grad
            o.grad += out.grad
        out._backward = _backward
        return out
    def __mul__(self, o):
        o = Value.lift(o); out = Value(self.data * o.data, (self, o)); COUNT["ops"] += 1
        def _backward():
            self.grad += o.data * out.grad
            o.grad += self.data * out.grad
        out._backward = _backward
        return out
    def __pow__(self, k):                                               # k is a plain number
        out = Value(self.data ** k, (self,)); COUNT["ops"] += 1
        def _backward():
            self.grad += k * self.data ** (k - 1) * out.grad
        out._backward = _backward
        return out
    def _unary(self, value, local_derivative):
        out = Value(value, (self,)); COUNT["ops"] += 1
        def _backward():
            self.grad += local_derivative * out.grad                    # local derivative stored from the forward pass
        out._backward = _backward
        return out
    def tanh(self): t = math.tanh(self.data); return self._unary(t, 1 - t * t)
    def exp(self):  e = math.exp(self.data); return self._unary(e, e)
    def log(self):  return self._unary(math.log(self.data), 1 / self.data)
    def sin(self):  return self._unary(math.sin(self.data), math.cos(self.data))
    __radd__, __rmul__ = __add__, __mul__
    def __neg__(self): return self * -1.0
    def __sub__(self, o): return self + (-Value.lift(o))
    def __rsub__(self, o): return Value.lift(o) + (-self)
    def __truediv__(self, o): return self * Value.lift(o) ** -1
    def __rtruediv__(self, o): return Value.lift(o) * self ** -1

    def backward(self):
        # put every node after its parents (depth-first search without recursion), then run the trace backwards
        order, seen, stack = [], set(), [(self, False)]
        while stack:
            node, done = stack.pop()
            if done:
                order.append(node)
            elif id(node) not in seen:
                seen.add(id(node)); stack.append((node, True))
                stack.extend((p, False) for p in node._parents if id(p) not in seen)
        self.grad = 1.0
        for node in reversed(order):
            if node._backward is not None:
                node._backward(); COUNT["ops"] += 1
        return len(order)                                               # number of nodes in the graph

4. The cost: forward mode needs one pass per input, reverse mode one pass per output¶

For $f: \mathbb{R}^n \to \mathbb{R}^m$, one forward-mode pass with tangent $v$ gives a Jacobian–vector product $J v$ (one column of $J$ when $v = e_j$), so the full Jacobian needs $n$ passes. One reverse-mode pass with seed $u$ gives a vector–Jacobian product $u^\top J$ (one row of $J$), so it needs $m$ passes. A training loss has $m = 1$ output and millions of inputs (the weights), so reverse mode wins: one backward pass gives the whole gradient.

We count elementary operations for $f(x) = \sum_{i=1}^{n-1} \tanh(x_i x_{i+1})$ with both engines.

def chain_sum(xs):
    total = xs[0] * 0.0
    for i in range(len(xs) - 1):
        total = total + (xs[i] * xs[i + 1]).tanh()
    return total

rows = []
for n in [10, 30, 100, 300]:
    xv = np.random.default_rng(n).standard_normal(n).tolist()
    COUNT["ops"] = 0; t0 = time.perf_counter()
    g_fwd = [chain_sum([Dual(v, 1.0 if i == j else 0.0) for i, v in enumerate(xv)]).b for j in range(n)]
    t_fwd, ops_fwd = time.perf_counter() - t0, COUNT["ops"]
    COUNT["ops"] = 0; t0 = time.perf_counter()

5. Backpropagation is reverse mode on a network¶

A network is a program made of layers, so backpropagation is reverse-mode AD. Each layer needs only its vector–Jacobian product: given $\bar y = \partial L / \partial y$, return the adjoints of its inputs and weights. For a batch $X$ (one row per example):

  • linear layer $Y = XW + b$: $\bar X = \bar Y W^\top$, $\bar W = X^\top \bar Y$, $\bar b = $ the column sums of $\bar Y$;
  • $H = \tanh(A)$, elementwise: $\bar A = \bar H \odot (1 - H^2)$ (no Jacobian matrix is ever formed);
  • logistic loss on scores $s$: $\bar s = (\sigma(s) - y)/n$.

To apply these, the backward pass needs $X$ and $H$ from the forward pass: frameworks store activations, and that is where most training memory goes. We write a 2-8-1 tanh network this way and compare its gradients with the scalar engine and with PyTorch on two moons.

X_tr, y_tr = make_moons(n_samples=100, noise=0.1, random_state=0)
X_te, y_te = make_moons(n_samples=500, noise=0.1, random_state=1)
H = 8

def init_params(seed=0):
    rng = np.random.default_rng(seed)
    return {"W1": rng.normal(0, 1, (2, H)), "b1": np.zeros(H), "W2": rng.normal(0, 1, H) / np.sqrt(H), "b2": np.zeros(())}

def numpy_loss_grad(P, X, y):
    A1 = X @ P["W1"] + P["b1"]                      # forward pass; X and H1 are kept for the backward pass
    H1 = np.tanh(A1)
    s = H1 @ P["W2"] + P["b2"]
    loss = np.mean(np.logaddexp(0, s) - y * s)
    s_bar = (1 / (1 + np.exp(-s)) - y) / len(y)     # backward pass: one VJP per layer, last layer first
    A1_bar = np.outer(s_bar, P["W2"]) * (1 - H1 ** 2)
    grads = {"W2": H1.T @ s_bar, "b2": s_bar.sum(), "W1": X.T @ A1_bar, "b1": A1_bar.sum(axis=0)}
    return loss, grads

def engine_loss_grad(P, X, y):
    V = {k: np.vectorize(Value, otypes=[object])(np.asarray(p)) for k, p in P.items()}   # one Value per weight
    total = Value(0.0)
    for xi, yi in zip(X.tolist(), y.tolist()):
        h_ = [(V["W1"][0, j] * xi[0] + V["W1"][1, j] * xi[1] + V["b1"][j]).tanh() for j in range(H)]
        s = V["b2"].item()
        for j in range(H):
            s = s + V["W2"][j] * h_[j]
        total = total + ((s.exp() + 1).log() - s * yi)
    loss = total * (1.0 / len(y))
    nodes = loss.backward()
    grads = {k: np.vectorize(lambda v: v.grad)(arr) for k, arr in V.items()}
    return loss.data, grads, nodes

def torch_loss_grad(P, X, y):
    T = {k: torch.tensor(v, requires_grad=True) for k, v in P.items()}
    s = torch.tanh(torch.tensor(X) @ T["W1"] + T["b1"]) @ T["W2"] + T["b2"]
    loss = torch.nn.functional.binary_cross_entropy_with_logits(s, torch.tensor(y, dtype=torch.float64))
    loss.backward()
    return loss.item(), {k: t.grad.numpy() for k, t in T.items()}

6. Training the network, twice¶

The scalar engine and the NumPy version run the same mathematics, so from the same starting weights plain gradient descent should follow the same path. We train both for 100 steps (step size 2.0), then continue with NumPy only, which is much faster.

def train(loss_grad, P, steps, lr=2.0):
    P = {k: np.array(v, dtype=float) for k, v in P.items()}
    losses = []
    for _ in range(steps):
        out = loss_grad(P, X_tr, y_tr)
        losses.append(out[0])
        for k in P:
            P[k] = P[k] - lr * out[1][k]
    return P, losses

t0 = time.perf_counter(); P_en, loss_en = train(engine_loss_grad, P0, 100); t_en = time.perf_counter() - t0
t0 = time.perf_counter(); P_np, loss_np = train(numpy_loss_grad, P0, 100); t_np = time.perf_counter() - t0

7. Reverse mode differentiates any program¶

Nothing above needed "layers". Below, the program is six steps of Newton's method for $\sqrt a$, $x \leftarrow \frac{1}{2}(x + a/x)$, started at $x = 1$. The engine records the loop like any other trace, and the derivative of the output with respect to $a$ should be close to $\frac{d}{da}\sqrt a = \frac{1}{2\sqrt a}$.

a_val = Value(2.0)
x_it = Value(1.0)
for _ in range(6):
    x_it = 0.5 * (x_it + a_val / x_it)
x_it.backward()
print(f"Newton's method after 6 steps: {x_it.data:.15f} (sqrt 2 = {math.sqrt(2):.15f})")
print(f"derivative with respect to a through the loop: {a_val.grad:.15f};  1 / (2 sqrt 2) = {1 / (2 * math.sqrt(2)):.15f}")

What to notice¶

  • Every method gave the same derivatives (sections 1–3): $\partial f/\partial x_1 = 5.5$ and $\partial f/\partial x_2 = 1.7163378145$ from the hand formulas, two forward-mode passes with dual numbers, one reverse-mode pass over a 9-node graph, and PyTorch in both modes. Central differences were off by 3.1e-11 and 8.7e-11. $(2 + \varepsilon)^3$ came out as Dual(8, 12), and $g = xy + x^2$ at (3, 2) had gradient (8, 3).
  • Forward mode pays per input, reverse mode per output (section 4). For $n$ = 10, 30, 100 and 300 inputs, forward mode needed 280, 2,640, 29,800 and 269,400 operations, and reverse mode 56, 176, 596 and 1,796 (one forward and one backward sweep, $6n - 4$ here), with identical gradients. In the saved run that was 86.8 ms against 1.95 ms at $n = 300$. One forward pass gave the first column of the Jacobian and one reverse pass its second row, as theory says.
  • Backpropagation is reverse mode written with VJPs (section 5). The NumPy layer-by-layer VJPs, the scalar engine and PyTorch gave the same loss (0.694916983862) and gradients that differ by at most 8.3e-17. For 100 examples the scalar engine built 8,236 Python objects, while the NumPy version stored 1,100 numbers; both keep forward values for the backward pass, which is why training memory grows with batch size and depth.
  • Same path, very different speed (section 6). Over 100 steps of gradient descent the two implementations' losses never differed by more than 2.2e-16 (both reached 0.121774), but the scalar engine took 7.2 s and NumPy 4.0 ms in the saved run. After 3,000 NumPy steps the network reached training accuracy 1.000 and test accuracy 0.996 on 500 new points.
  • Reverse mode went through a loop (section 7). The derivative of six Newton steps with respect to $a$ was 0.353553390593274, equal to $1/(2\sqrt 2)$ to every printed digit, because six steps already reach $\sqrt 2$ to machine precision. With fewer steps the derivative of the program and the derivative of $\sqrt a$ differ (assignment 5).
  • Operation counts are exact; the times depend on the machine. Real frameworks use the same two modes on whole arrays, with many more operations and memory-saving tricks.
