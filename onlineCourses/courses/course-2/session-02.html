1. $Ax = b$ means "mix the columns of $A$"¶

The product $Ax$ is a weighted sum of the columns of $A$, with the entries of $x$ as weights. So solving $Ax = b$ asks: which mix of the columns gives $b$?

By hand first: solve $x_1 + x_2 = 3$, $x_1 + 2x_2 = 5$ by elimination (subtract the first equation from the second). Then write $b = (3, 5)$ as a mix of the columns $(1, 1)$ and $(1, 2)$.

import time
import numpy as np
import scipy.linalg
import matplotlib.pyplot as plt
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression

np.random.seed(0)
np.set_printoptions(precision=4, suppress=True)

A = np.array([[1.0, 1.0], [1.0, 2.0]])
b = np.array([3.0, 5.0])
x = np.linalg.solve(A, b)
print("solution x =", x)
print(f"mix of the columns: {x[0]:.0f} * {A[:, 0]} + {x[1]:.0f} * {A[:, 1]} = {x[0] * A[:, 0] + x[1] * A[:, 1]}")

2. Rank: one solution, none, or infinitely many¶

The column space of $A$ is the set of all mixes $Ax$. The rank of $A$ is the number of independent columns, which is the dimension of the column space. For $A$ with $n$ columns:

  • if $b$ is not in the column space, there is no solution; a test is $\operatorname{rank}([A \mid b]) > \operatorname{rank}(A)$;
  • if $b$ is in it and the rank is $n$, there is exactly one solution;
  • if $b$ is in it and the rank is below $n$, there are infinitely many: some $z \ne 0$ has $Az = 0$ (the null space), and adding $z$ to a solution gives another.

By hand first: in $A_1$ with rows (1, 2) and (2, 4), the second column is twice the first. How many solutions are there for $b = (3, 6)$, and for $b = (1, 3)$? Find a nonzero $z$ with $A_1 z = 0$.

A1 = np.array([[1.0, 2.0], [2.0, 4.0]])
for b1 in [np.array([3.0, 6.0]), np.array([1.0, 3.0])]:
    r, r_aug = np.linalg.matrix_rank(A1), np.linalg.matrix_rank(np.column_stack([A1, b1]))
    verdict = "no solution" if r_aug > r else ("one solution" if r == A1.shape[1] else "infinitely many solutions")
    print(f"b = {b1}: rank(A1) = {r}, rank([A1 | b]) = {r_aug} -> {verdict}")

z = np.array([2.0, -1.0])                      # A1 z = 0, a direction in the null space
x_part = np.array([3.0, 0.0])                  # one solution for b = (3, 6)
print("A1 z =", A1 @ z, "; A1 (3, 0) =", A1 @ x_part, "; A1 ((3, 0) + 5 z) =", A1 @ (x_part + 5 * z))
try:
    np.linalg.solve(A1, np.array([3.0, 6.0]))
except np.linalg.LinAlgError as e:
    print("np.linalg.solve on A1:", e)

3. Least squares by hand: a line through three points¶

With more equations than unknowns, $Ax = b$ usually has no solution. Least squares chooses the $x$ that minimizes $\|Ax - b\|^2$. Its gradient is $2A^\top(Ax - b)$, so at the minimum the normal equations hold: $$A^\top A\, \hat x = A^\top b .$$ Geometrically, $A\hat x$ is the point of the column space closest to $b$: the projection of $b$. The residual $r = b - A\hat x$ is orthogonal to every column, $A^\top r = 0$.

By hand first: fit $y = c + m t$ to the points $(t, y) = (0, 1), (1, 1), (2, 4)$. Here $A$ has rows $(1, 0), (1, 1), (1, 2)$ and $b = (1, 1, 4)$. Compute $A^\top A$, $A^\top b$, solve the 2 × 2 system, then the residual $r$ and $A^\top r$.

t = np.array([0.0, 1.0, 2.0])
A3 = np.column_stack([np.ones(3), t])
b3 = np.array([1.0, 1.0, 4.0])
print("A^T A =\n", A3.T @ A3, "\nA^T b =", A3.T @ b3)
x_hat = np.linalg.solve(A3.T @ A3, A3.T @ b3)
r3 = b3 - A3 @ x_hat
print("x_hat (intercept c, slope m) =", x_hat)
print("fitted values", A3 @ x_hat, " residual r =", r3, " A^T r =", A3.T @ r3, " sum of squares =", r3 @ r3)

P = A3 @ np.linalg.inv(A3.T @ A3) @ A3.T       # projection matrix, formed here only to look at it
print("6 P =\n", 6 * P)
print("P b equals the fitted values:", np.allclose(P @ b3, A3 @ x_hat), "; P P = P:", np.allclose(P @ P, P), "; P symmetric:", np.allclose(P, P.T))

4. QR by hand: Gram–Schmidt on the same three points¶

QR writes $A = QR$, where $Q$ has orthonormal columns ($Q^\top Q = I$) and $R$ is upper triangular. Then $A^\top A = R^\top R$ and $A^\top b = R^\top Q^\top b$, so the normal equations become the triangular system $$R\, \hat x = Q^\top b,$$ solved by back substitution, without ever forming $A^\top A$.

By hand first (Gram–Schmidt): $q_1 = (1, 1, 1)/\sqrt 3$. Remove from $a_2 = (0, 1, 2)$ its part along $q_1$: $a_2 - (a_2 \cdot q_1) q_1 = (-1, 0, 1)$, so $q_2 = (-1, 0, 1)/\sqrt 2$. Then $R$ has rows $(\sqrt 3, \sqrt 3)$ and $(0, \sqrt 2)$, and $Q^\top b = (6/\sqrt 3,\ 3/\sqrt 2)$. Back-substitute to get $\hat x$.

def gram_schmidt(A):
    # classical Gram-Schmidt for a tall matrix with independent columns (fine for small examples)
    Q, R = np.zeros(A.shape), np.zeros((A.shape[1], A.shape[1]))
    for j in range(A.shape[1]):
        v = A[:, j].copy()
        for i in range(j):
            R[i, j] = Q[:, i] @ A[:, j]
            v -= R[i, j] * Q[:, i]
        R[j, j] = np.linalg.norm(v)
        Q[:, j] = v / R[j, j]
    return Q, R

Q3, R3 = gram_schmidt(A3)
print("Q =\n", Q3, "\nR =\n", R3, "\n(sqrt 3 =", np.sqrt(3), ", sqrt 2 =", np.sqrt(2), ")")
print("Q^T b =", Q3.T @ b3, "; x_hat from R x = Q^T b:", scipy.linalg.solve_triangular(R3, Q3.T @ b3))
Qn, Rn = np.linalg.qr(A3)
print("np.linalg.qr gives R =\n", Rn, "\n(the signs may differ; the solution does not):", scipy.linalg.solve_triangular(Rn, Qn.T @ b3))

5. Linear regression on the diabetes data, three ways¶

The diabetes data in scikit-learn has 442 patients and 10 measurements (age, sex, body-mass index bmi, blood pressure bp and six blood-serum values s1–s6), already centred and scaled. The target is a measure of how much the disease progressed one year later. We add a column of ones for the intercept and fit the weights with the normal equations, with np.linalg.lstsq (which uses the SVD of session 3) and with QR, and compare with scikit-learn.

diab = load_diabetes()
X, y = diab.data, diab.target
A = np.column_stack([np.ones(len(X)), X])              # 442 x 11
names = ["intercept"] + diab.feature_names

w_normal = np.linalg.solve(A.T @ A, A.T @ y)

Q, R = np.linalg.qr(A)                                  # reduced QR: Q is 442 x 11, R is 11 x 11
w_qr = scipy.linalg.solve_triangular(R, Q.T @ y)
sk = LinearRegression().fit(X, y)
w_sk = np.r_[sk.intercept_, sk.coef_]

print("weights:", ", ".join(f"{n} {w:.1f}" for n, w in zip(names, w_lstsq)))

6. Why not compute the inverse?¶

np.linalg.inv(A) @ b gives the same answer as np.linalg.solve(A, b) in exact arithmetic, but forming the inverse costs about three times the arithmetic of the LU factorization that solve uses, and its rounding errors are larger. We measure time on a random 1000 × 1000 system, and the relative residual $\|Ax - b\| / \|b\|$ on the 10 × 10 Hilbert matrix (entries $1/(i + j - 1)$), a classic ill-conditioned test matrix. Session 10 explains conditioning in depth.

rng = np.random.default_rng(0)
M = rng.standard_normal((1000, 1000)); bm = rng.standard_normal(1000)
t0 = time.perf_counter(); x_solve = np.linalg.solve(M, bm); t_solve = time.perf_counter() - t0
t0 = time.perf_counter(); x_inv = np.linalg.inv(M) @ bm; t_inv = time.perf_counter() - t0
rel_res = lambda K, xx, bb: np.linalg.norm(K @ xx - bb) / np.linalg.norm(bb)
print(f"random 1000 x 1000: solve time {t_solve * 1e3:.1f} ms, inverse time {t_inv * 1e3:.1f} ms")
print(f"random 1000 x 1000: relative residual, solve {rel_res(M, x_solve, bm):.1e}, inverse {rel_res(M, x_inv, bm):.1e}")

H = scipy.linalg.hilbert(10)
x_true = np.ones(10); bh = H @ x_true
xs, xi = np.linalg.solve(H, bh), np.linalg.inv(H) @ bh
print(f"Hilbert 10 x 10, condition number {np.linalg.cond(H):.1e}")
print(f"  relative residual: solve {rel_res(H, xs, bh):.1e}, inverse {rel_res(H, xi, bh):.1e}")
print(f"  relative error in x: solve {np.linalg.norm(xs - x_true) / np.linalg.norm(x_true):.1e}, inverse {np.linalg.norm(xi - x_true) / np.linalg.norm(x_true):.1e}")

np.linalg.lstsq handles the same problem with the SVD. It treats tiny singular values as zero and returns the minimum-norm solution: of all the weight vectors with the smallest residual, the one with the smallest length. For two identical columns that means splitting the weight equally. Below, s1 is duplicated, and we move along the null-space direction (+1 on one copy, −1 on the other) to see that the fit does not change while the length of $w$ does.

j = diab.feature_names.index("s1") + 1                 # column of s1 in A
A_dup = np.column_stack([A, A[:, j]])
w_min, _, rank_dup, _ = np.linalg.lstsq(A_dup, y, rcond=None)
w_ne = np.linalg.solve(A_dup.T @ A_dup, A_dup.T @ y)
sse = lambda w: np.sum((y - A_dup @ w) ** 2)

9. A larger regression (NOT RUN here)¶

The California housing data has 20,640 districts and 8 features. The three methods agree there too; time them.

# NOT RUN: needs a download of the California housing data through fetch_california_housing.
import time
import numpy as np
import scipy.linalg
from sklearn.datasets import fetch_california_housing

Xc, yc = fetch_california_housing(return_X_y=True)           # 20,640 x 8
Xc = (Xc - Xc.mean(0)) / Xc.std(0)
Ac = np.column_stack([np.ones(len(Xc)), Xc])

def fit_qr(A, b):
    Q, R = np.linalg.qr(A)
    return scipy.linalg.solve_triangular(R, Q.T @ b)

fits = {"normal equations": lambda: np.linalg.solve(Ac.T @ Ac, Ac.T @ yc),
        "lstsq": lambda: np.linalg.lstsq(Ac, yc, rcond=None)[0],
        "QR": lambda: fit_qr(Ac, yc)}
for name, fit in fits.items():
    t0 = time.perf_counter(); w = fit(); dt = time.perf_counter() - t0
    print(f"{name:17s} time {dt * 1e3:.1f} ms, weights {np.round(w, 3)}")

What to notice¶

  • Columns and rank (sections 1–2). $b = (3, 5)$ is 1 × column 1 + 2 × column 2. For the rank-1 matrix $A_1$, $b = (3, 6)$ had infinitely many solutions (adding $5z$ with $A_1 z = 0$ still gave (3, 6)), $b = (1, 3)$ had none, and np.linalg.solve refused $A_1$ with "Singular matrix".
  • The hand calculation matched (sections 3–4): $A^\top A$ with rows (3, 3) and (3, 5), $A^\top b = (6, 9)$, $\hat x = (0.5, 1.5)$, residual (0.5, −1, 0.5), $A^\top r = 0$ and a sum of squares of 1.5. Gram–Schmidt gave $R$ with rows $(\sqrt 3, \sqrt 3)$ and $(0, \sqrt 2)$ and $Q^\top b = (3.4641, 2.1213)$; NumPy's QR flipped the signs of $Q$ and $R$ and gave the same $\hat x$.
  • Three methods, one answer (section 5). On the diabetes data the normal equations, QR and scikit-learn agreed with lstsq to within 3.4e-12, the residual was orthogonal to every column (largest $|A^\top r|$ = 6.2e-13) and the training $R^2$ was 0.518. The condition number of $A^\top A$ (51,631) is the square of that of $A$ (227): the normal equations lose about twice as many digits, which matters only for ill-conditioned data (session 10).
  • The inverse was slower and less accurate (section 6). In the saved run the inverse took 57.7 ms against 19.4 ms for solve. On the Hilbert matrix the relative residual was 1.6e-16 with solve and 3.4e-05 with the inverse. Even solve got $x$ right only to 1.2e-05, because the problem itself is ill-conditioned (condition number 1.6e13): a small residual does not promise a small error.
  • Against expectation, the normal equations rarely failed loudly (section 7). With a duplicated feature they raised LinAlgError for only 2 of the 10 features (s4, s5). For the other 8 they returned an answer without any warning, with an arbitrary split between the copies, such as 2225.61 and −3017.79 for s1. The sums were right and the fit was identical, so the predictions were fine, but the weights meant nothing. lstsq returned the minimum-norm split, −396.09 for each copy (weight length 1268.0 against 3918.5).
  • A near-copy is worse than an exact copy. With noise of size 1e-6 added to the copy, nothing was singular any more: lstsq returned weights of −4,131,612 and 4,130,820 and lowered the sum of squares from 1,263,985.8 to 1,256,389.3 by fitting the noise.
