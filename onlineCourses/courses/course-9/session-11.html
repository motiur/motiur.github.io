The 2026 work¶

Erdős problem #728. In January 2026, Harmonic's Aristotle system produced a Lean proof (6 January) from an informal argument by an OpenAI model; Sothanaphan wrote it up for humans (arXiv 2601.07421). The problem was the first regarded as fully resolved autonomously by an AI system. The proof chooses $n = 2m$, $b = m$, $a = m + k$, which turns the factorial divisibility $a!\,b! \mid n!\,(a+b-n)!$ into the binomial divisibility $\binom{m+k}{k} \mid \binom{2m}{m}$ with $k$ of order $\log m$, and checks it prime by prime with Kummer's theorem.

The unit distance conjecture. On 20 May 2026 OpenAI announced that an internal model had found a counterexample to Erdős's 1946 unit distance conjecture. Nine outside mathematicians wrote a companion paper with a short, human-checked version (arXiv 2605.20695).

This lab is a toy illustration, not a reproduction. We verify Kummer's theorem and binomial divisibility for small numbers, and count unit distances in square grids, the classical construction. Finite checks cannot prove statements about infinitely many numbers, and nothing here reproduces the 2026 constructions.

1. Legendre's formula and Kummer's theorem¶

For a prime $p$, write $v_p(x)$ for the exponent of $p$ in $x$. Legendre: $v_p(n!) = \sum_{i \ge 1} \lfloor n/p^i \rfloor$. Kummer: $v_p\binom{a+b}{a}$ equals the number of carries when $a$ and $b$ are added in base $p$. We check Kummer against direct computation for every $a, b \le 120$ and every prime $p \le 23$.

import math
import time
import numpy as np
import matplotlib.pyplot as plt

np.random.seed(0)

def v_p(x, p):                        # exponent of p in the integer x > 0
    v = 0
    while x % p == 0:
        x //= p
        v += 1
    return v

def v_p_factorial(n, p):              # Legendre's formula
    total, q = 0, p
    while q <= n:
        total += n // q
        q *= p
    return total

def carries(a, b, p):                 # number of carries when adding a + b in base p
    count = carry = 0
    while a or b or carry:
        carry = 1 if a % p + b % p + carry >= p else 0
        count += carry
        a, b = a // p, b // p
    return count

def primes_upto(n):
    sieve = np.ones(n + 1, dtype=bool)
    sieve[:2] = False
    for i in range(2, int(n ** 0.5) + 1):
        if sieve[i]:
            sieve[i * i::i] = False
    return [int(p) for p in np.nonzero(sieve)[0]]

assert v_p_factorial(100, 5) == v_p(math.factorial(100), 5) == 24
checks = mismatches = 0
for p in primes_upto(23):
    for a in range(121):
        for b in range(121):
            checks += 1
            mismatches += carries(a, b, p) != v_p(math.comb(a + b, a), p)
print(f"Kummer's theorem: {checks} checks, {mismatches} mismatches")
print(f"example: 3 + 3 in base 2 has {carries(3, 3, 2)} carries, and C(6, 3) = {math.comb(6, 3)} = 4 x 5")

2. From problem #728 to binomial coefficients¶

Problem #728 asks for $a, b > \varepsilon n$ with $a!\,b! \mid n!\,(a+b-n)!$ and a gap $a + b - n$ of order $\log n$, between $C_1 \log n$ and $C_2 \log n$. (The write-up also keeps $a, b \le (1-\varepsilon)n$.) The upper limit on the gap matters: without it, $a = b = n$ would answer the question trivially, as the formal-conjectures project notes about the version shown on the website. With $n = 2m$, $b = m$, $a = m + k$:

$\dfrac{n!\,(a+b-n)!}{a!\,b!} = \dfrac{(2m)!\,k!}{(m+k)!\,m!} = \binom{2m}{m} \Big/ \binom{m+k}{k}$,

so the divisibility holds exactly when $\binom{m+k}{k}$ divides $\binom{2m}{m}$. For $k = 1$ it always holds: $\binom{2m}{m}/(m+1)$ is the Catalan number.

for m, k in [(10, 3), (100, 7), (1000, 9)]:
    lhs = math.factorial(2 * m) * math.factorial(k) * math.comb(m + k, k)
    rhs = math.factorial(m + k) * math.factorial(m) * math.comb(2 * m, m)
    print(f"m = {m:4d}, k = {k}: identity holds: {lhs == rhs};  C(m+k, k) divides C(2m, m): {math.comb(2 * m, m) % math.comb(m + k, k) == 0}")
print("k = 1 works for every m from 1 to 2,000:", all(math.comb(2 * m, m) % (m + 1) == 0 for m in range(1, 2001)))

3. Checking divisibility prime by prime¶

$\binom{m+k}{k} \mid \binom{2m}{m}$ holds exactly when, for every prime $p \le m + k$, adding $m + k$ in base $p$ makes no more carries than adding $m + m$. We run this Kummer test for every $m$ from 1,000 to 1,999 and every $k$ from 1 to 40 (vectorized over $m$ and $k$), and compare it with direct division of the big integers.

def carries_array(A, B, p):           # carries for whole arrays of numbers at once
    A, B = A.copy(), B.copy()
    carry, count = np.zeros_like(A), np.zeros_like(A)
    while A.any() or B.any() or carry.any():
        carry = (A % p + B % p + carry >= p).astype(A.dtype)
        count += carry
        A, B = A // p, B // p
    return count

t0 = time.time()
ms, ks = np.arange(1000, 2000), np.arange(1, 41)
Mg, Kg = np.meshgrid(ms, ks, indexing="ij")
kummer_ok = np.ones(Mg.shape, dtype=bool)
for p in primes_upto(int(ms.max() + ks.max())):
    kummer_ok &= carries_array(Mg, Kg, p) <= carries_array(Mg, Mg, p)
t_kummer = time.time() - t0
t0 = time.time()
direct_ok = np.array([[math.comb(2 * int(m), int(m)) % math.comb(int(m) + int(k), int(k)) == 0 for k in ks] for m in ms])
print(f"{kummer_ok.size} pairs (m, k): Kummer test and direct division agree on all of them: {(kummer_ok == direct_ok).all()}"
      f"   ({t_kummer:.1f} s and {time.time() - t0:.1f} s)")
frac = kummer_ok.mean(axis=0)
for k in [1, 2, 5, 10, 20, 30, 40]:
    print(f"k = {k:2d} (about {k / np.log(2 * ms).mean():.1f} x ln n): divisible for {frac[k - 1]:.3f} of m in [1000, 2000)")
all_k = [int(m) for m, row in zip(ms, kummer_ok) if row.all()]
print(f"m in [1000, 2000) that work for every k from 1 to 40: {all_k}")

plt.figure(figsize=(8, 3.5))
plt.plot(ks, frac, "o-")
plt.axvline(np.log(2 * ms).mean(), color="gray", ls=":", label="k = ln n (n = 2m)")
plt.xlabel("k (the gap a + b - n)"); plt.ylabel("share of m in [1000, 2000)")
plt.title("How often C(m+k, k) divides C(2m, m)")
plt.legend(); plt.grid(alpha=0.3); plt.show()

4. Why some $m$ work: carries in small bases¶

The write-up's strategy chooses $m$ so that doubling $m$ makes many carries in every small base $p$, which needs many base-$p$ digits of at least $p/2$. Look at $m = 1328$, which works for every $k \le 40$.

def digits(x, p):
    out = []
    while x:
        out.append(x % p)
        x //= p
    sep = "" if p <= 10 else "."                         # digits of 10 or more are separated by dots
    return sep.join(str(d) for d in reversed(out))

5. Unit distances in a square grid¶

Erdős's unit distance problem asks for $u(n)$, the largest number of pairs at distance exactly 1 among $n$ points in the plane. The classical construction takes an $s \times s$ grid ($n = s^2$), finds the squared distance $N$ that occurs most often, and scales the grid so that $\sqrt{N}$ becomes 1. A distance $\sqrt{N}$ can occur in many directions when $N$ has many representations as a sum of two squares; the number of representations is $r_2(N) = 4(d_1(N) - d_3(N))$, where $d_j$ counts divisors that are $j$ mod 4.

def best_unit_count(s):
    d = np.arange(-(s - 1), s)
    DX, DY = np.meshgrid(d, d, indexing="ij")
    key = (DX**2 + DY**2).ravel()
    weight = ((s - np.abs(DX)) * (s - np.abs(DY))).ravel()     # how many grid pairs have this difference vector
    count = np.bincount(key, weights=weight)
    count[0] = 0
    N = int(np.argmax(count))
    return N, int(count[N] // 2)                                 # each unordered pair was counted twice

def r2(N):                            # brute force: integer points on the circle x^2 + y^2 = N
    r = int(math.isqrt(N))
    return sum(1 for x in range(-r, r + 1) for y in range(-r, r + 1) if x * x + y * y == N)

def r2_jacobi(N):
    divs = [d for d in range(1, N + 1) if N % d == 0]
    return 4 * (sum(d % 4 == 1 for d in divs) - sum(d % 4 == 3 for d in divs))

def factor(N):
    out, p = [], 2
    while p * p <= N:
        while N % p == 0:
            out.append(p)
            N //= p
        p += 1
    return out + ([N] if N > 1 else [])

pts = np.array([(i, j) for i in range(10) for j in range(10)])
sq = ((pts[:, None, :] - pts[None, :, :]) ** 2).sum(-1)
N10, c10 = best_unit_count(10)
print(f"10 x 10 grid: best squared distance {N10}, {c10} pairs by formula, {(sq == N10).sum() // 2} pairs by brute force")

What to notice¶

  • Kummer's theorem held everywhere we looked: 131,769 checks with 0 mismatches. The prime-by-prime test agreed with direct division of the big integers on all 40,000 pairs $(m, k)$.
  • Why $m = 1328$ works for every $k \le 40$: in bases 3, 5 and 7, many of its digits are at least about half the base, so $m + m$ makes at least as many carries as any $m + k$, for every prime up to 79.
  • Large gaps are common in this range. $k = 1$ always works (the Catalan numbers). The share of $m$ in [1000, 2000) that work falls from 1.000 at $k = 1$ to 0.681 at $k = 10$ and 0.201 at $k = 40$ (about 5 ln n), but it does not reach zero. So a computer search could never settle #728: the problem is about all large $n$, which only a proof (here, one checked in Lean) can cover.
  • Number theory makes distances repeat. The best squared distance in each grid was a product of primes of the form $4k + 1$ (5, 65, 325, 1105, 5525), with $r_2(N)$ from 8 to 48, matching Jacobi's formula. Unit-distance pairs per point grew from 1.92 (25 points) to 17.35 (102,400 points).
  • Against intuition: $\log(\text{pairs})/\log(n)$ stayed between 1.20 and 1.25 over the whole range, although for square grids it must tend to 1 (a point has at most $r_2(N)$ partners at squared distance $N$, and $r_2(N)$ grows more slowly than any power of $N$). Data of this size cannot tell $n^{1.25}$ from $n^{1 + c/\log\log n}$, which is why the 2026 counterexample needed a proof, not a plot.
