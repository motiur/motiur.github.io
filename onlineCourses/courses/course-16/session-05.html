1. By hand first: the table for two four-letter words¶

The edit distance (Levenshtein distance) between two strings is the smallest number of single-letter insertions, deletions and substitutions that turns the first into the second.

Dynamic programming has four parts. Write them down before any code:

  1. Subproblems: $D[i][j]$ = the edit distance between the first $i$ letters of $a$ and the first $j$ letters of $b$.
  2. Recurrence: look at the last letters. Either they are aligned with each other (cost 0 if equal, 1 if not), or the last letter of $a$ is deleted, or the last letter of $b$ is inserted: $$D[i][j] = \min\big(D[i-1][j-1] + [a_i \ne b_j],\;\; D[i-1][j] + 1,\;\; D[i][j-1] + 1\big), \qquad D[i][0] = i,\; D[0][j] = j .$$
  3. Order: row by row, left to right, so that the three neighbours are ready.
  4. Answer: the bottom-right cell $D[m][n]$.

Session 4's view: every cell is a node of a grid graph with three incoming edges, the row-by-row order is a topological order, and the edit distance is the length of the shortest path from the top-left corner to the bottom-right corner.

On paper: fill the 5 × 5 table for $a$ = NEAR and $b$ = EARN. Compared position by position, all four letters differ. Is the edit distance 4? Then run the cell.

import random, time

def edit_table(a, b, sub_cost=1):
    # D[i][j] = edit distance between a[:i] and b[:j]. a and b can be strings (letters) or lists (words).
    m, n = len(a), len(b)
    D = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        D[i][0] = i                                        # delete the first i items of a
    for j in range(1, n + 1):
        D[0][j] = j                                        # insert the first j items of b
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            D[i][j] = min(D[i - 1][j - 1] + (sub_cost if a[i - 1] != b[j - 1] else 0),    # match or substitution
                          D[i - 1][j] + 1,                                                # deletion
                          D[i][j - 1] + 1)                                                # insertion
    return D

def show_table(a, b, D):

    for i, row in enumerate(D):
        print(f"  {(['""'] + list(a))[i]:>2s} " + "".join(f"{v:3d}" for v in row))

2. Three implementations: plain recursion, memoized recursion, bottom-up table¶

The recurrence can be run in three ways.

  • Plain recursion: a function that calls itself three times. It solves the same subproblem again and again: the number of calls grows exponentially with the length.
  • Memoized recursion: the same function with a dictionary that remembers every $(i, j)$ it has solved. Each of the $m \cdot n$ subproblems is solved once.
  • Bottom-up table: the loop of section 1. Also $m \cdot n$ cells, with no recursion.

All three must return the same number. We count the calls of the first, the subproblems solved by the second and the cells of the third. The plain recursion always makes all three calls, so its count depends only on the two lengths, and we can also get it from a table of its own: $\text{calls}(i, j) = 1 + \text{calls}(i-1, j-1) + \text{calls}(i-1, j) + \text{calls}(i, j-1)$. That lets us print the count for 20-letter words without waiting for it.

def lev_recursive(a, b):
    calls = 0
    def rec(i, j):
        nonlocal calls
        calls += 1
        if i == 0: return j
        if j == 0: return i
        return min(rec(i - 1, j - 1) + (a[i - 1] != b[j - 1]), rec(i - 1, j) + 1, rec(i, j - 1) + 1)
    return rec(len(a), len(b)), calls

def lev_memo(a, b):
    memo, solved = {}, 0
    def rec(i, j):
        nonlocal solved
        if i == 0: return j
        if j == 0: return i
        if (i, j) not in memo:
            solved += 1                                    # a subproblem that is really computed
            memo[(i, j)] = min(rec(i - 1, j - 1) + (a[i - 1] != b[j - 1]), rec(i - 1, j) + 1, rec(i, j - 1) + 1)
        return memo[(i, j)]
    return rec(len(a), len(b)), solved

def lev_table(a, b):
    return edit_table(a, b)[-1][-1], len(a) * len(b)

def predicted_calls(m, n):
    # the number of calls of the plain recursion, from its own recurrence
    T = [[1] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            T[i][j] = 1 + T[i - 1][j - 1] + T[i - 1][j] + T[i][j - 1]
    return T[m][n]

3. The backtrace gives an alignment, and the alignment gives the word error rate¶

The table holds more than the distance. Start in the bottom-right cell and walk back: at each cell, find a neighbour that explains its value. A diagonal step is a match or a substitution, a step up is a deletion, a step left is an insertion. The path is an alignment of the two sequences. (When several neighbours explain the value there are several best alignments; the code prefers the diagonal.)

Nothing in the table needs letters. With words as the units, the same code scores a speech recognizer. If the reference has $N$ words and the best alignment has $S$ substitutions, $D$ deletions and $I$ insertions, then

$$\text{WER} = \frac{S + D + I}{N} .$$

The number of reference words that were recognized correctly is $H = N - S - D$ (the hits). Insertions are extra words: they are not in $N$, so the WER can be larger than 1.

The sentences below are examples written for this notebook. Course 12 session 2 uses WER and the character error rate on Bangla speech and shows why both sides must be normalized in the same way first.

def align(ref, hyp):
    # the operations that turn ref into hyp, read from a backtrace through the table
    D = edit_table(ref, hyp)
    i, j, ops = len(ref), len(hyp), []
    while i > 0 or j > 0:
        if i > 0 and j > 0 and D[i][j] == D[i - 1][j - 1] + (ref[i - 1] != hyp[j - 1]):
            ops.append(("ok " if ref[i - 1] == hyp[j - 1] else "sub", ref[i - 1], hyp[j - 1])); i -= 1; j -= 1
        elif i > 0 and D[i][j] == D[i - 1][j] + 1:
            ops.append(("del", ref[i - 1], "")); i -= 1
        else:
            ops.append(("ins", "", hyp[j - 1])); j -= 1
    return ops[::-1]

def wer(ref, hyp, show=True):
    ref_words, hyp_words = ref.split(), hyp.split()
    ops = align(ref_words, hyp_words)
    S, Dl, I, H = (sum(o[0] == kind for o in ops) for kind in ("sub", "del", "ins", "ok "))
    N = len(ref_words)
    if show:
        print("  reference :", ref)
        print("  hypothesis:", hyp)
        print("  alignment : " + " | ".join(f"{r} -> {h}" if k == "sub" else f"{k.strip()} {r or h}" for k, r, h in ops))
    print(f"  N = {N}, hits H = {H}, S = {S}, D = {Dl}, I = {I}:  WER = ({S} + {Dl} + {I}) / {N} = {(S + Dl + I) / N:.3f};  correct reference words H / N = {H / N:.3f}")

4. Less memory and fewer cells: two rows, and a band around the diagonal¶

Two rows. Row $i$ of the table needs only row $i - 1$. If we want the distance and not the alignment, we keep two rows: $O(\min(m, n))$ memory instead of $O(m \cdot n)$. The time is still $m \cdot n$ cell updates. (Hirschberg (1975) showed, for the longest common subsequence, how to get the alignment as well in linear memory, by divide and conquer; the same method works for edit distance.)

A band. A cell $(i, j)$ lies $|i - j|$ steps away from the diagonal, and every step away from the diagonal costs an insertion or a deletion. So if the distance is at most $k$, a best path never leaves the band $|i - j| \le k$, and we need only about $(2k + 1) \cdot n$ cells. This is the idea of Ukkonen (1985). We do not know the distance in advance, so edit_banded(a, b, k) answers a yes/no question first: it returns the distance if it is at most $k$, and None otherwise. It also stops early when every cell of a row is already above $k$: values never get smaller from one row to the next. Doubling $k$ until the answer is not None finds the distance in $O(d \cdot n)$ cells for distance $d$.

The test strings are synthetic: a random string of 1,500 letters from ACGT, and a copy with 40 random edits.

def edit_two_rows(a, b):
    # the distance with two rows of the table; returns (distance, cells filled)
    if len(b) > len(a):
        a, b = b, a                                        # the rows get the length of the shorter string
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur, ai = [i] + [0] * len(b), a[i - 1]
        for j in range(1, len(b) + 1):
            cur[j] = min(prev[j - 1] + (ai != b[j - 1]), prev[j] + 1, cur[j - 1] + 1)
        prev = cur
    return prev[-1], len(a) * len(b)

def edit_banded(a, b, k):
    # only the cells with |i - j| <= k. Returns (distance, cells) if the distance is <= k, else (None, cells).
    m, n, INF = len(a), len(b), 10 ** 9
    if abs(m - n) > k:
        return None, 0                                     # the corner cell (m, n) is outside the band
    prev_lo, prev_hi, prev = 0, min(n, k), list(range(min(n, k) + 1))     # row 0, columns 0 .. k
    cells = 0
    for i in range(1, m + 1):
        lo, hi, ai = max(0, i - k), min(n, i + k), a[i - 1]
        cur = [INF] * (hi - lo + 1)                        # row i, columns lo .. hi
        if lo == 0:
            cur[0] = i
        for j in range(max(1, lo), hi + 1):
            best = prev[j - 1 - prev_lo] + (ai != b[j - 1])                # the diagonal neighbour is always in the band
            if j <= prev_hi and prev[j - prev_lo] + 1 < best:              # the neighbour above, if it is in the band
                best = prev[j - prev_lo] + 1
            if j > lo and cur[j - 1 - lo] + 1 < best:                      # the neighbour on the left, if it is in the band
                best = cur[j - 1 - lo] + 1
            cur[j - lo] = best
            cells += 1
        if min(cur) > k:
            return None, cells                             # early exit: no later cell can be <= k
        prev_lo, prev_hi, prev = lo, hi, cur
    d = prev[n - prev_lo]
    return (d if d <= k else None), cells

            del s[rng.randrange(len(s))]

5. The same table with another score: longest common subsequence and ROUGE-L¶

Change the recurrence a little and the same table answers a different question. A subsequence keeps some items of a sequence, in their order, not necessarily next to each other. The longest common subsequence (LCS) of two sequences:

$$L[i][j] = \begin{cases} L[i-1][j-1] + 1 & \text{if } a_i = b_j \\ \max(L[i-1][j],\; L[i][j-1]) & \text{otherwise} \end{cases} \qquad L[i][0] = L[0][j] = 0 .$$

ROUGE-L (Lin 2004) scores a candidate summary against a reference summary with the LCS of their words: recall $R = \text{LCS} / (\text{reference length})$, precision $P = \text{LCS} / (\text{candidate length})$, and $F = (1 + \beta^2) P R / (R + \beta^2 P)$; with $\beta = 1$ this is the harmonic mean of the two. Words must come in the same order to count, but they need not be neighbours.

LCS and edit distance are close relatives: if substitutions are not allowed (give them cost 2, the price of a deletion plus an insertion), the distance is $m + n - 2 \cdot \text{LCS}$. The cell checks this on random strings. The two summaries are examples written for this notebook.

def lcs(a, b):
    # the longest common subsequence itself, by a backtrace through the table
    m, n = len(a), len(b)
    L = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            L[i][j] = L[i - 1][j - 1] + 1 if a[i - 1] == b[j - 1] else max(L[i - 1][j], L[i][j - 1])
    i, j, out = m, n, []
    while i > 0 and j > 0:
        if a[i - 1] == b[j - 1]:
            out.append(a[i - 1]); i -= 1; j -= 1
        elif L[i - 1][j] >= L[i][j - 1]:
            i -= 1
        else:
            j -= 1
    return out[::-1]

def rouge_l(reference, candidate, beta=1.0):
    ref, cand = reference.split(), candidate.split()
    common = lcs(ref, cand)
    R, P = len(common) / len(ref), len(common) / len(cand)
    F = (1 + beta ** 2) * P * R / (R + beta ** 2 * P) if common else 0.0
    return common, P, R, F

6. Global alignment with scores: Needleman–Wunsch¶

Biologists compare DNA and protein sequences with the same table, but they maximize a score instead of minimizing a count: a match earns $+1$, a mismatch costs $-1$, and a gap (an insertion or a deletion) costs $-2$ here. This is global alignment (Needleman & Wunsch 1970):

$$F[i][j] = \max\big(F[i-1][j-1] + s(a_i, b_j),\;\; F[i-1][j] + \text{gap},\;\; F[i][j-1] + \text{gap}\big), \qquad F[i][0] = i \cdot \text{gap},\; F[0][j] = j \cdot \text{gap} .$$

To trust the table, we compare it with brute force on tiny inputs: a recursion that tries every alignment and keeps the best score. The number of alignments grows very fast, and the same table shape can count them too: replace "max of three scores" by "sum of three counts". (Session 6 builds on this idea of changing the two operations.)

Local alignment (Smith & Waterman 1981) finds the best-matching pieces of two sequences with three small changes; that is the second exercise. The DNA strings are made up.

MATCH, MISMATCH, GAP = 1, -1, -2

def needleman_wunsch(a, b):
    m, n = len(a), len(b)
    F = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1): F[i][0] = i * GAP
    for j in range(1, n + 1): F[0][j] = j * GAP
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            s = MATCH if a[i - 1] == b[j - 1] else MISMATCH
            F[i][j] = max(F[i - 1][j - 1] + s, F[i - 1][j] + GAP, F[i][j - 1] + GAP)
    i, j, top, bottom = m, n, [], []                       # backtrace: build the two aligned rows
    while i > 0 or j > 0:
        if i > 0 and j > 0 and F[i][j] == F[i - 1][j - 1] + (MATCH if a[i - 1] == b[j - 1] else MISMATCH):
            top.append(a[i - 1]); bottom.append(b[j - 1]); i -= 1; j -= 1
        elif i > 0 and F[i][j] == F[i - 1][j] + GAP:
            top.append(a[i - 1]); bottom.append("-"); i -= 1
        else:
            top.append("-"); bottom.append(b[j - 1]); j -= 1
    return F[m][n], "".join(top[::-1]), "".join(bottom[::-1])

def brute_force_alignment(a, b):
    # try every alignment; returns (best score, number of alignments tried)
    tried = 0
    def rec(i, j, score):
        nonlocal tried
        if i == len(a) and j == len(b):
            tried += 1
            return score
        best = -10 ** 9
        if i < len(a) and j < len(b):
            best = max(best, rec(i + 1, j + 1, score + (MATCH if a[i] == b[j] else MISMATCH)))
        if i < len(a):
            best = max(best, rec(i + 1, j, score + GAP))
        if j < len(b):
            best = max(best, rec(i, j + 1, score + GAP))
        return best
    return rec(0, 0, 0), tried

def count_alignments(m, n):
    C = [[1] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            C[i][j] = C[i - 1][j - 1] + C[i - 1][j] + C[i][j - 1]     # the same three neighbours, added instead of compared
    return C[m][n]

7. Time against length¶

The count says $m \cdot n$ cell updates: for two strings of the same length $n$, doubling $n$ should multiply the time by 4, a straight line of slope 2 on log–log axes. We time the two-row version on random strings. These are timings in pure Python, so they vary from run to run; the number of cells does not.

No much faster exact algorithm is expected: Backurs & Indyk (2015) showed that an algorithm with time $O(n^{2 - \delta})$ for some $\delta > 0$ would contradict the Strong Exponential Time Hypothesis, a well-known conjecture about the hardness of the satisfiability problem. In practice, speed comes from filling fewer cells (section 4) and from compiled code.

What to notice¶

(Written from the run above. The counts are exact and will be the same on your machine; the timings will not.)

  1. Edit distance is not a position-by-position comparison. NEAR and EARN differ in all four positions, but the table's corner says 2: delete the first N, keep E A R, insert an N at the end. The table found this by trying every way to line the two words up.
  2. The same recurrence costs an exponential number of calls or a quadratic number of cells. All three implementations agreed on all 300 random pairs. For two strings of length 9 the plain recursion made 2,193,844 calls, about 5.5 times more for each extra letter, where the memoized version solved 81 subproblems and the table has 81 cells. For two 20-letter words the recursion would need 390,815,720,696,161 calls; the table has 400 cells.
  3. The backtrace turns the table into an alignment. The English pair has one substitution, one deletion and one insertion in 9 reference words: WER 0.333. The Bangla pair has WER 0.571 (S = 2, D = 1, I = 1, N = 7); note that করে দেখব in place of করব costs two errors. A best alignment is not always unique: the code had to choose which of the two words to call the insertion.
  4. WER is not "the share of wrong words". The recognizer that kept writing after thank you got WER 2.500 with both reference words correct. And two outputs with the same WER of 0.250 had 0.750 and 1.000 of the reference words correct: one had two substitutions, the other two extra words at the end.
  5. Two rows are enough for the distance, and a band is enough when the strings are close. For the 1,500-letter pair (distance 34) two rows hold 3,002 numbers instead of 2,259,000 cells. Bands of 1, 2 and 4 failed without filling a single cell, because the lengths differ by 6. Bands of 8, 16 and 32 stopped early with None. The band of 64 gave the exact distance from 189,709 cells, 8.4% of the table, and doubling from 1 to 64 used 302,907 cells in all, 7.5 times fewer than the full table. A band that is too narrow never returns a wrong number, only None; a band that is far too wide wastes work (57% of the table at $k = 512$).
  6. The same table, other scores. ROUGE-L gave 0.600, 0.500 and 0.300 to three candidates made of the same nine words in different orders: it rewards words in the reference's order. The distance without substitutions equalled $m + n - 2 \cdot \text{LCS}$ on all 300 random pairs. Needleman–Wunsch aligned the two DNA strings with 7 matches and 3 gaps (score 1), the same score that brute force found after trying 598,417 alignments, and the two agreed on all 200 random pairs. For two sequences of length 100 there are about 2 × 10⁷⁵ alignments and 10,000 cells.
  7. Time follows the cell count, roughly. Doubling the length multiplied the cells by exactly 4. The fitted slope of the measured time was close to 2 and a little above it in this run: the time per cell is not perfectly constant in pure Python. Conclusions about growth should rest on the counts.
  8. Everything here is small and synthetic. For real evaluation, text normalization matters as much as the algorithm (Course 12 session 2), and dynamic time warping applies the same table to signals (Course 12 session 3).
