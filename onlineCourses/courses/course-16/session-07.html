1. By hand first: a three-token tree where greedy loses¶

A language model gives a probability to every next token. Decoding means choosing a whole output, one token at a time. All possible outputs form a tree of prefixes: the root is the empty string, and every node has one child per token. With $V$ tokens and $T$ steps the tree has $V^T$ leaves, so we cannot look at all of them.

The toy model below has three tokens, A, B and C, and we want the most probable string of length 2 (nine leaves). Greedy decoding keeps only the best prefix at each step. Beam search with width $b$ keeps the $b$ best prefixes. Do it on paper first:

  • after step 1 the prefixes have probability A 0.5, B 0.4, C 0.1;
  • after A the next token is A 0.4, B 0.3, C 0.3; after B it is A 0.9, B 0.05, C 0.05; after C it is A 0.6, B 0.3, C 0.1.

Which string does greedy return? Which string does a beam of width 2 return? One call of the model gives a score for all three tokens: how many scores does each method compute?

import math, time, heapq, re, itertools
import numpy as np
import matplotlib.pyplot as plt
from scipy import stats

t_start = time.time()

# next-token probabilities of the toy model; the key is the prefix so far
P = {"":  {"A": 0.5, "B": 0.4, "C": 0.1},
     "A": {"A": 0.4, "B": 0.3, "C": 0.3},
     "B": {"A": 0.9, "B": 0.05, "C": 0.05},
     "C": {"A": 0.6, "B": 0.3, "C": 0.1}}

def toy_beam(width, depth=2):
    beams, n_scores = [(1.0, "")], 0
    for t in range(depth):
        cand = []
        for prob, prefix in beams:
            n_scores += len(P[prefix])                       # one model call scores every token
            cand += [(prob * q, prefix + tok) for tok, q in P[prefix].items()]
        beams = heapq.nlargest(width, cand)                  # keep the `width` most probable prefixes
        print(f"  step {t + 1}: keep " + ", ".join(f"{s} ({p:.2f})" for p, s in beams))
    return beams[0], n_scores

leaves = sorted(((P[""][a] * P[a][b], a + b) for a in "ABC" for b in "ABC"), reverse=True)
print("all 9 strings of length 2, most probable first:")
print("  " + ", ".join(f"{s} {p:.2f}" for p, s in leaves))
for width in [1, 2]:
    print(f"beam width {width}" + (" (greedy):" if width == 1 else ":"))
    (p, s), n = toy_beam(width)
    print(f"  returns {s} with probability {p:.2f}, after computing {n} scores")
print(f"exhaustive search: {leaves[0][1]} with probability {leaves[0][0]:.2f}, after computing {3 + 9} scores")

2. A character trigram model¶

We need a language model that is small enough to search exactly, so that we can say how far greedy and beam search are from the true optimum. A character trigram model predicts the next character from the two characters before it:

$$P(c \mid a, b) = \frac{\text{count}(a, b, c) + k}{\text{count}(a, b) + kV}.$$

The constant $k$ (add-$k$ smoothing, here $k = 0.1$) gives every character a small probability, also after pairs that the model never saw. The training text is twelve short paragraphs written for this notebook (about 3,500 characters; a real model reads billions). We keep 28 symbols: the space, the full stop and the letters a to z. Like the hidden Markov model of session 6, it has a small number of states (here the last two characters). It stands in for the neural language models of Course 4: both give a score to every next token.

3. Greedy, beam and exact search¶

The task: after a two-character prompt, find the most probable continuation of exactly $T = 20$ characters.

  • Beam search with width $b$ expands each kept prefix (one model call, $V$ scores), which gives $bV$ candidates, and keeps the best $b$ with a heap. Cost: about $T \cdot b \cdot V$ scores. Width 1 is greedy decoding.
  • Exact search. A trigram model looks only at the last two characters, so two prefixes that end in the same pair have the same future. We keep the best prefix for each of the $V^2$ pairs: this is the Viterbi algorithm of session 6, with $V^2$ states. Cost: about $T \cdot V^3$ scores, instead of $V^T$ leaves. A neural language model looks at the whole prefix, so it has no such table, and its search is always approximate.

We check the exact search against brute force for $T = 3$ (all $28^3 = 21{,}952$ strings), then run every method on 100 prompts: the 100 most frequent character pairs of the text.

def beam_search(a, b, T, width):
    # Most probable continuation of T characters after the pair (a, b), found with a beam of the given width.
    beams, n_scores = [(0.0, (a, b))], 0                     # (log-probability, ids so far)
    for t in range(T):
        cand = []
        for lp, seq in beams:
            row = logp[seq[-2], seq[-1]]                     # one model call: V scores for this prefix
            n_scores += V
            cand += [(lp + row[c], seq + (c,)) for c in range(V)]
        beams = heapq.nlargest(width, cand)                  # a heap keeps the best `width` of the width * V candidates
    return beams[0][0], beams[0][1], n_scores

def exact_search(a, b, T):
    # The most probable continuation of exactly T characters: Viterbi over the V * V states (pairs of characters).
    delta = np.full((V, V), -np.inf); delta[a, b] = 0.0      # delta[x, y]: best log-probability of a prefix that ends in x, y
    back, n_scores = [], 0
    for t in range(T):
        n_scores += int(np.isfinite(delta).sum()) * V        # every reachable state scores V next characters
        cand = delta[:, :, None] + logp                      # cand[x, y, c]
        back.append(cand.argmax(axis=0))                     # for the new state (y, c): the best x before it
        delta = cand.max(axis=0)
    y, c = np.unravel_index(delta.argmax(), delta.shape)
    seq = [int(c), int(y)]
    for bp in reversed(back):                                # follow the back-pointers
        seq.append(int(bp[seq[-1], seq[-2]]))
    return float(delta.max()), tuple(seq[::-1]), n_scores

4. What search returns, and what sampling returns¶

Now look at the text itself. From the prompt ". " (the start of a sentence) we produce 60 characters with greedy search, beam search, exact search, and four sampling rules:

  • sampling draws the next character from the model's distribution; temperature $\tau$ divides the log-probabilities before the softmax ($\tau < 1$ sharpens the distribution);
  • top-k keeps the $k$ most probable characters and renormalizes; top-p (nucleus) keeps the smallest set whose probabilities add up to at least $p$ (Course 5 session 7 shows how these settings change Bangla text).

Two measurements: the mean log-probability per character under the model, and the share of distinct trigrams in the output (1.0 means no three-character piece is repeated). For the sampling rules we report the mean of 200 samples and print the first one. The last lines show why a fixed seed matters.

def sample_text(a, b, T, rng, temperature=1.0, top_k=None, top_p=None):
    seq, total = [a, b], 0.0
    for t in range(T):
        row = logp[seq[-2], seq[-1]]
        q = np.exp(row / temperature); q /= q.sum()
        if top_k is not None:
            keep = np.argpartition(-q, top_k - 1)[:top_k]    # the k most probable characters, found without a full sort
            kept = np.zeros(V); kept[keep] = q[keep]; q = kept / kept.sum()
        if top_p is not None:
            order = np.argsort(-q, kind="stable")
            before = np.cumsum(q[order]) - q[order]          # probability mass before each character, in sorted order
            q[order[before >= top_p]] = 0.0; q /= q.sum()    # keep the smallest set that reaches top_p
        c = int(rng.choice(V, p=q))
        total += row[c]                                      # log-probability under the model itself
        seq.append(c)
    return tuple(seq), total

def distinct_trigrams(seq):
    grams = list(zip(seq, seq[1:], seq[2:]))
    return len(set(grams)) / len(grams)

The most probable sentence. So far the length was fixed. Real decoders stop when the model produces an end symbol. Let the full stop be our end symbol: for each length $L$ we find, exactly, the most probable continuation of $L$ characters that ends with its first full stop (the same Viterbi table, with the full stop forbidden before the last position). Every extra character multiplies the probability by a number below 1, so watch which length wins, and what happens if we divide the log-probability by the length instead.

DOT = char_id["."]
def best_sentence_by_length(a, b, max_len):
    # For L = 1 .. max_len: the most probable continuation of L characters whose only full stop is the last one.
    inside = logp.copy(); inside[:, :, DOT] = -np.inf        # no full stop before the end
    delta = np.full((V, V), -np.inf); delta[a, b] = 0.0
    back, out = [], []
    for L in range(1, max_len + 1):
        end = delta + logp[:, :, DOT]                        # close the sentence at this length
        x, y = np.unravel_index(end.argmax(), end.shape)
        seq = [DOT, int(y), int(x)]
        for bp in reversed(back):
            seq.append(int(bp[seq[-1], seq[-2]]))
        out.append((float(end.max()), decode(seq[::-1][2:])))
        cand = delta[:, :, None] + inside
        back.append(cand.argmax(axis=0)); delta = cand.max(axis=0)
    return out

5. Selecting the top k of 50,000 logits¶

Beam search, top-k sampling and top-p sampling all need the largest few of $V$ scores at every step, and a real vocabulary has $V \approx 50{,}000$ tokens or more. Three ways to find the $k = 50$ largest:

  • sort everything: $O(V \log V)$ comparisons;
  • a min-heap of size $k$: keep the $k$ largest seen so far; each new score is compared with the smallest of them (the root) and replaces it if it is larger, at a cost of $O(\log k)$. Worst case $O(V \log k)$, when every score replaces the root. If the scores arrive in random order, the root is replaced only about $k \ln(V/k)$ times, so the expected number of comparisons is close to $V$;
  • quickselect (Hoare 1961): choose a random pivot, split the scores into larger and smaller, and continue in the part that contains the $k$-th largest. Expected $O(V)$, worst case $O(V^2)$ (with very unlucky pivots). The median-of-medians rule makes the worst case linear (Blum et al. 1973).

To count comparisons exactly we wrap each score in an object whose < operator adds one to a counter. Python's sorted and heapq.nlargest use only <. Timings of the plain NumPy and Python functions follow, on lines that contain the word "time".

V_BIG, K_TOP = 50_000, 50
rng = np.random.default_rng(0)
logits = rng.normal(0.0, 2.0, V_BIG)                         # stand-in for the scores of one decoding step

class Counted:
    # A score that counts how many times it is compared.
    __slots__ = ("v", "i")
    n_cmp = 0
    def __init__(self, v, i):
        self.v, self.i = v, i
    def __lt__(self, other):
        Counted.n_cmp += 1
        return self.v < other.v

def quickselect_top(items, k, rng):
    # The k largest items, in any order, by Hoare's selection with a random pivot.
    out = []
    while k > 0:
        pivot = items[int(rng.integers(len(items)))]
        larger, smaller = [], []
        for x in items:
            if x is not pivot:
                (larger if pivot < x else smaller).append(x)     # one comparison per item
        if len(larger) >= k:
            if len(larger) == k:
                return out + larger
            items = larger                                   # the k largest are all in `larger`
        else:
            out += larger + [pivot]; k -= len(larger) + 1; items = smaller
    return out

def count_comparisons(fn, values):
    items = [Counted(v, i) for i, v in enumerate(values)]
    Counted.n_cmp = 0
    chosen = fn(items)
    return sorted(o.i for o in chosen), Counted.n_cmp

methods = {"sort everything": lambda items: sorted(items, reverse=True)[:K_TOP],

6. Top-p (nucleus) without sorting everything¶

Top-p sampling (Holtzman et al. 2020) keeps the smallest set of tokens whose probabilities add up to at least $p$, the nucleus. The textbook implementation sorts all $V$ probabilities, takes cumulative sums and cuts. But we only need the probabilities in order until their sum passes $p$. So: select the $m$ largest with a linear-time selection (np.argpartition, no order inside), check whether they already hold mass $p$, and multiply $m$ by 4 if not; then sort only those $m$.

The size of the nucleus depends on the shape of the distribution. We try three Zipf-like distributions over 50,000 tokens ($p_r \propto r^{-s}$, stored in random order), and two next-character distributions of the trigram model.

def top_p_full_sort(p, top_p):
    order = np.argsort(-p)                                   # sorts all V probabilities
    m = int(np.searchsorted(np.cumsum(p[order]), top_p)) + 1 # the smallest prefix whose sum reaches top_p
    return order[:m], len(p)

def top_p_partial(p, top_p, start=64):
    m = min(start, len(p))
    while True:
        top = np.argpartition(-p, m - 1)[:m] if m < len(p) else np.arange(len(p))    # the m largest, unordered: O(V)
        if m == len(p) or p[top].sum() >= top_p:
            order = top[np.argsort(-p[top])]                 # sort only these m
            return order[:int(np.searchsorted(np.cumsum(p[order]), top_p)) + 1], m
        m = min(4 * m, len(p))

7. Randomness as argmax: the Gumbel-max trick¶

Sampling can be turned into a maximization. Draw independent noise $g_i = -\ln(-\ln u_i)$ with $u_i$ uniform on (0, 1): this is the Gumbel distribution. Then

$$\arg\max_i \big(\log p_i + g_i\big)$$

is an exact sample from $p$. Taking the $k$ largest perturbed scores instead of the largest gives $k$ different items, distributed exactly as if we had drawn them one after another without replacement (Kool et al. 2019). So one top-k selection, the algorithm of section 5, samples $k$ distinct tokens at once; stochastic beam search is built on this.

We test both claims on 8 items: a chi-square test of 200,000 Gumbel-max draws against $p$; then, for $k = 3$, a chi-square test of the ordered triples against the exact probabilities of drawing without replacement (336 possible triples), and the inclusion frequencies of each item next to NumPy's own rng.choice(..., replace=False).

rng = np.random.default_rng(0)
p = np.array([0.30, 0.22, 0.16, 0.12, 0.08, 0.06, 0.04, 0.02])
n_items, N = len(p), 200_000
gumbel = lambda size: -np.log(-np.log(rng.random(size)))    # Gumbel(0, 1) noise from uniform numbers

draws = np.argmax(np.log(p) + gumbel((N, n_items)), axis=1)  # the Gumbel-max trick, N times
freq = np.bincount(draws, minlength=n_items)
chi2, pval = stats.chisquare(freq, N * p)
print("item | probability | Gumbel-max frequency")
for i in range(n_items):
    print(f"{i:4d} | {p[i]:11.3f} | {freq[i] / N:20.4f}")
print(f"chi-square test against p: statistic {chi2:.2f} with {n_items - 1} degrees of freedom, p-value {pval:.3f}")

k = 3
exact_seq, exact_incl = {}, np.zeros(n_items)                # drawing without replacement, by enumeration
for tup in itertools.permutations(range(n_items), k):
    prob, rest = 1.0, 1.0
    for i in tup:
        prob *= p[i] / rest; rest -= p[i]
    exact_seq[tup] = prob; exact_incl[list(tup)] += prob
triple_prob = np.array(list(exact_seq.values()))
triple_code = np.array([a * 64 + b * 8 + c for a, b, c in exact_seq])
def gumbel_top_k(n_draws):
    top = np.argsort(-(np.log(p) + gumbel((n_draws, n_items))), axis=1)[:, :k]   # the k largest perturbed scores, in order
    return top, np.bincount(top[:, 0] * 64 + top[:, 1] * 8 + top[:, 2], minlength=512)[triple_code]

      f"statistic {chi2_k:.1f} with {len(exact_seq) - 1} degrees of freedom, p-value {pval_k:.3f} (smallest expected count {N * triple_prob.min():.1f})")

M = 20_000
incl_numpy = np.zeros(n_items)
for _ in range(M):
    incl_numpy[rng.choice(n_items, size=k, replace=False, p=p)] += 1
incl_numpy /= M
print(f"item | probability | P(item is among the {k}): exact | Gumbel-top-k ({N:,d} draws) | rng.choice ({M:,d} draws)")
for i in range(n_items):

print(f"largest difference from the exact value: Gumbel-top-k {np.abs(incl_gumbel - exact_incl).max():.4f}, rng.choice {np.abs(incl_numpy - exact_incl).max():.4f}")
print(f"note: k * p would be wrong; for item 0 it gives {k * p[0]:.2f}, but the exact value is {exact_incl[0]:.4f}")

What to notice¶

(Written from the saved run. Every count, probability and p-value below is the same on every run, because the seeds are fixed. The lines that contain the word "time" change from run to run.)

  1. Greedy can lose at the first step. In the three-token tree, greedy returned AA (probability 0.20) after 6 scores, a beam of width 2 returned BA (0.36) after 9 scores, and looking at all nine leaves cost 12 scores. The best string starts with the second-best first token.
  2. Beam search is an approximation, and we can measure how good it is. On 100 prompts and 20 characters, greedy found the most probable continuation for 54 prompts; beams of width 2, 4, 8 and 16 found it for 71, 83, 94 and 100. The work grew in proportion to the width: 560, 1,092, 2,156, 4,284 and 8,540 scores per prompt. Exact search by the Viterbi algorithm needed 395,948 scores, which is nothing next to the $8.77 \times 10^{28}$ leaves of the tree, but it exists only because a trigram model has $28^2$ states. In this run a wider beam was never worse than a narrower one (0 cases for every pair of widths); that is a measurement, not a guarantee.
  3. The most probable text is not good text. From the start of a sentence, greedy, beam 16 and exact search all returned the same 60 characters, the the the ...: log-probability −0.649 per character and only 0.08 distinct trigrams. The training text has −1.492 and 0.88. So the model's own best string is far more probable than real text, and much more repetitive. Sampling gave 0.93 distinct trigrams at temperature 1.0, 0.78 at temperature 0.7, 0.78 with top-k = 5 and 0.88 with top-p = 0.9. The samples are not English either: the model saw 3,557 characters, and after a pair it never saw (only 286 of 784 pairs occur) every character is equally likely, which no decoding rule can repair.
  4. The most probable sentence is very short. With the full stop as the end symbol, the most probable sentence of any length up to 40 was it. (three characters, log-probability −5.914). Dividing by the length turns the problem around: the best score per character was at the longest allowed length, 40, with the the ... and. Both rules fail, in opposite directions. This is why real decoders use a milder length penalty and a limited beam (first TODO).
  5. Selecting the top 50 of 50,000 needs far fewer comparisons than sorting. A full sort made 715,841 comparisons, a heap of size 50 made 52,508, and quickselect 159,732; all three gave NumPy's answer. The heap's count depends on the order of the input: 52,508 for random order (close to $V$, because the root was rarely replaced), 335,937 for ascending order (its worst case, where every score replaces the root) and 50,238 for descending order. Quickselect made about $3.2V$ comparisons here, more than the heap in random order, although its bound $O(V)$ looks better than $O(V \log k)$: the bounds describe different cases. In the saved run np.argpartition plus a sort of 50 values was three to four times as fast as np.sort of everything, and on Python lists heapq.nlargest was about eight times as fast as sorted.
  6. Top-p needs order only inside the nucleus. For the three Zipf-like distributions the nucleus for $p = 0.9$ had 15,996, 2,166 and 6 tokens of 50,000, and the partial method sorted 16,384, 4,096 and 64 values instead of 50,000, with the same result. For $p = 0.99$ on the two flatter distributions the nucleus was 44,615 and 32,894 tokens, and the partial method ended by sorting all 50,000 after several wasted selection passes: it helps only when the nucleus is small. In the trigram model the nucleus had 4 characters after th, 15 after e and 7 at the start of a sentence; a fixed top-k cannot adapt like this.
  7. Gumbel noise turns sampling into argmax. The frequencies of 200,000 Gumbel-max draws matched $p$ (chi-square p-value 0.486). For the three largest perturbed scores, item 0 was included with frequency 0.7397 against the exact 0.7365 for drawing without replacement; the simple guess $k \cdot p = 0.90$ is wrong.
  8. One result went against expectation, and we kept it. The chi-square test of the ordered triples gave a p-value of 0.047, just below the usual 0.05 line, and item 0's inclusion frequency was 0.0032 above the exact value (about three standard errors). We did not change the seed. A correct sampler gives a p-value below 0.05 in one run out of twenty, so one such value is weak evidence. The honest next step is a new, larger experiment: the same test with five new seeds and 2,000,000 draws each gave p-values 0.821, 0.373, 0.091, 0.252 and 0.313. A real difference would give smaller p-values with more draws, not larger ones.
