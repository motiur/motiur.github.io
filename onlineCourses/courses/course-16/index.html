Algorithms Behind Modern AI

The data structures and algorithms inside modern AI systems, built from scratch and measured: arrays and cost, hashing and Bloom filters, tokenizers with heaps and tries, computation graphs and topological sort, dynamic programming from edit distance to the CTC loss, beam search and sampling, automata for constrained decoding, nearest-neighbour indexes, caches, queues and batching, and randomized algorithms for data pipelines.

  • Hashing
  • Tokenizers
  • Dynamic programming
  • Search & decoding
  • Vector indexes
  • Caches & queues

Sessions

  1. 01

    Counting cost: arrays, memory and Big-O for models

    Count the multiply–adds of matrix products and of self-attention and compare the counts with measured time, read an array's strides to tell views from copies, count the copies behind amortized appends, and build CSR sparse storage to see when sparse beats dense.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  2. 02

    Hashing: dictionaries, the hashing trick and Bloom filters

    Build an open-addressing hash table and compare its probe counts with Knuth's formulas, see why Python salts string hashes, train a classifier on hashed features of several sizes, and measure the errors of a Bloom filter and a count–min sketch against their formulas.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  3. 03

    Tokenizers: byte-pair encoding with heaps, linked lists and tries

    Train byte-pair encoding twice, by recounting everything and with linked symbols, a pair index and a heap, check that both give the same merges while counting their work, and encode text by replaying merges and by longest match in a trie.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  4. 04

    Computation graphs: topological sort and automatic differentiation

    Order a computation graph with Kahn's algorithm and with depth-first search, run reverse-mode differentiation as one backward sweep and check it against PyTorch, count the cost of walking every path instead, and shrink a graph with dead-code elimination, constant folding and common-subexpression elimination.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  5. 05

    Dynamic programming I: edit distance and alignment

    Compute edit distance by plain recursion, with memoization and with a table and count the work of each, read an alignment and a word error rate from the backtrace, save memory and cells with two rows and a band, and reuse the same table for ROUGE-L and for DNA alignment.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  6. 06

    Dynamic programming II: Viterbi, the forward algorithm and CTC

    Find the best path and the total probability over exponentially many paths with one table, implement Viterbi and the forward algorithm in log space, and compute the CTC loss from scratch, checked against brute force and against PyTorch.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  7. 07

    Decoding: heaps, beam search and sampling

    Implement greedy, beam and exact search for a small language model, select the top-k and top-p tokens without sorting everything, and sample with the Gumbel-max trick, counting the work each one does.

    Read notebook Colab Kaggle .ipynb Runs fully on CPU
  8. 08

    Automata and tries: constrained decoding and structured outputs

    Build a trie and a finite automaton from scratch, use them to mask a model's next-token choices so that every output fits a list or a pattern, and measure what the mask costs and how it changes the distribution.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  9. 09

    Nearest neighbours I: k-d trees, LSH and MinHash

    Build a k-d tree and count how its pruning fails as the dimension grows, build locality-sensitive hash indexes for cosine and Jaccard similarity, and find the near-duplicate documents of a corpus without comparing all pairs.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  10. 10

    Nearest neighbours II: HNSW, IVF and product quantization

    Build a graph index, an inverted-file index and a product quantizer for vector search from scratch, and measure recall against distance computations and bytes per vector for each.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  11. 11

    Serving models: caches, queues and batching

    Count the attention scores that a KV cache saves, build an LRU cache and a prefix tree that shares cached prompts, and simulate static and continuous batching for a model server.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell
  12. 12

    Randomized algorithms for data pipelines, and the capstone

    Sample uniformly from a stream, shuffle correctly, measure what a shuffle buffer does to sorted data, draw from a large discrete distribution in constant time, and start the capstone plan.

    Read notebook Colab Kaggle .ipynb 1 NOT RUN cell

Before you start

One notebook per session. Read them with their saved outputs on the course website or on GitHub, or open them in Google Colab or Kaggle Notebooks and run them from the top.

  • Every cell without a NOT RUN label was run once, top to bottom, on a CPU in November 2026 (Python 3.13, NumPy 2.5, SciPy 1.18, scikit-learn 1.9 and matplotlib 3.11, plus PyTorch 2.15 in sessions 4 and 6, where it only checks our own gradients and our own CTC loss), and the outputs are saved in the notebooks.
  • Operation counts (multiply–adds, probes, table cells, distance computations, cache hits) are exact, and a second, independent run reproduced every printed number. Timings do not reproduce: they come from one run on a shared server CPU, so treat them as rough and expect different numbers on your machine.
  • The data are synthetic or small: made-up words with a Zipf distribution, short English and Bangla texts written into the notebooks, random vectors with planted neighbours, simulated request traces, and scikit-learn's digits in session 12. Each notebook finishes in under a minute on a CPU. The numbers show how each algorithm behaves; they are not benchmark results.
  • Nothing extra needs installing for the runnable cells on Google Colab or Kaggle.
  • Cells marked TODO are exercises for students. Cells marked NOT RUN need a library, a model download or a GPU (the table below says what each needs). They were written from the libraries' documentation and have not been executed, so run each one before recording.
  • The batching experiments in session 11 are a simulation, not measurements of a real server.
  • Results that went against expectation are stated in each notebook's "What to notice" cell and in the course document. Examples: signed hashing helped the classifier only at the two smallest table sizes (session 2); the two tokenizer encoders differed on only 1.4% of word types (session 3); a wider beam did not always find the exact best string, and one sampling test gave a p-value of 0.047 (session 7); no LSH setting reached a recall of 0.9, and the pure-Python k-d tree was slower than NumPy brute force from 16 dimensions (session 9); HNSW's layers saved only a few dozen distance computations per query, and the simple "M nearest" link rule never reached a recall of 0.99 (session 10); first-in-first-out and random eviction were almost as good as LRU, and far behind the optimal rule (session 11); a shuffle buffer of 512 gave a slightly higher accuracy than a full shuffle, within the spread over seeds (session 12).
