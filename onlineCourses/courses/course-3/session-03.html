1. Setup and data¶

Everything runs on scikit-learn's 8x8 digits. The papers behind this session used CIFAR-10, ImageNet and much larger networks; here each experiment takes seconds, so we can see the effects but not measure them precisely.

import math, time
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F
import matplotlib.pyplot as plt
from threadpoolctl import threadpool_limits
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

torch.set_flush_denormal(True)

digits = load_digits()
X_all = torch.tensor(digits.data, dtype=torch.float32)
y_all = torch.tensor(digits.target)
Xtr, Xte, ytr, yte = train_test_split(X_all, y_all, test_size=0.25, random_state=0, stratify=y_all)
mu, sd = Xtr.mean(0), Xtr.std(0) + 1e-3
Xtr, Xte = (Xtr - mu) / sd, (Xte - mu) / sd
print(f"training set {tuple(Xtr.shape)}, test set {tuple(Xte.shape)}")


def mlp(seed, width=256):
    torch.manual_seed(seed)
    return nn.Sequential(nn.Linear(64, width), nn.ReLU(), nn.Linear(width, width), nn.ReLU(), nn.Linear(width, 10))


def accuracy(model, X, y):
    with torch.no_grad():
        return (model(X).argmax(1) == y).float().mean().item()

2. Networks can memorize random labels¶

Zhang et al. (2017) replaced CIFAR-10's labels with random ones and found that standard networks still reach zero training error. The same network, with the same training method, therefore generalizes well on real labels and not at all on random ones, so its size alone cannot explain why it generalizes. We repeat this with a 256-wide MLP and Adam.

def fit(labels, epochs=100, seed=0):
    model = mlp(seed)
    opt = torch.optim.Adam(model.parameters(), lr=1e-3)
    g = torch.Generator().manual_seed(seed)
    train_acc = []
    for epoch in range(epochs):
        for idx in torch.randperm(len(Xtr), generator=g).split(128):
            loss = F.cross_entropy(model(Xtr[idx]), labels[idx])
            opt.zero_grad(); loss.backward(); opt.step()
        train_acc.append(accuracy(model, Xtr, labels))
    return train_acc, accuracy(model, Xte, yte)


y_random = torch.randint(0, 10, (len(ytr),), generator=torch.Generator().manual_seed(1))
memo = {}
for name, labels in [("true labels", ytr), ("random labels", y_random)]:
    memo[name] = fit(labels)
    curve, test_acc = memo[name]
    first = next(i + 1 for i, a in enumerate(curve) if a >= 0.999)
    print(f"{name:13s}: training accuracy reaches 99.9% at epoch {first:3d}; test accuracy {test_acc:.3f}")
print("(chance level on the test set is 0.10)")

plt.figure(figsize=(6, 3.5))
for name, (curve, _) in memo.items():
    plt.plot(range(1, len(curve) + 1), curve, label=name)
plt.title("A 256-wide MLP fits both true and random labels")
plt.xlabel("epoch"); plt.ylabel("training accuracy"); plt.legend()
plt.tight_layout(); plt.show()

3. Double descent with random features¶

Belkin et al. (2019) showed the full curve. Take a fixed random ReLU layer with p features, φ(x) = relu(Wx + b), and fit only the output weights by least squares. When p < n (the number of training points) the fit is ordinary least squares; when p > n there are many exact fits, and we take the one with the smallest norm (np.linalg.lstsq returns it). We use n = 200 training images, of which about 20% have a wrong label, regress on one-hot targets, and average over five random draws of W. A ridge penalty λ‖β‖² is the comparison (Nakkiran et al. 2021).

rng = np.random.default_rng(0)
Xn, yn = digits.data / 16.0, digits.target
perm = rng.permutation(len(Xn))
tr_idx, te_idx = perm[:200], perm[200:]
m_, s_ = Xn[tr_idx].mean(0), Xn[tr_idx].std(0) + 1e-3
A_tr, A_te = (Xn[tr_idx] - m_) / s_, (Xn[te_idx] - m_) / s_
noisy = rng.random(200) < 0.2
labels_tr = np.where(noisy, rng.integers(0, 10, 200), yn[tr_idx])      # about 20% of labels replaced at random
Y_tr, y_te = np.eye(10)[labels_tr], yn[te_idx]
print(f"wrong training labels: {(labels_tr != yn[tr_idx]).mean():.2f}")

def random_features_test(p, ridge, seed):
    r = np.random.default_rng(100 + seed)
    W, b = r.normal(0, 1 / np.sqrt(64), (64, p)), r.normal(0, 1, p)
    F_tr, F_te = np.maximum(A_tr @ W + b, 0), np.maximum(A_te @ W + b, 0)
    if ridge == 0:
        beta = np.linalg.lstsq(F_tr, Y_tr, rcond=None)[0]                         # minimum-norm least squares
    else:
        beta = F_tr.T @ np.linalg.solve(F_tr @ F_tr.T + ridge * np.eye(200), Y_tr)  # ridge (dual form)
    pred = F_te @ beta
    return (pred.argmax(1) != y_te).mean(), ((pred - np.eye(10)[y_te]) ** 2).sum(1).mean()

ps = [10, 25, 50, 100, 150, 180, 200, 220, 250, 300, 400, 600, 1000, 2000]
dd = {}
for ridge in [0.0, 100.0]:
    res = np.array([[random_features_test(p, ridge, s) for s in range(5)] for p in ps])   # shape (len(ps), 5, 2)
    dd[ridge] = (res[:, :, 0].mean(1), np.median(res[:, :, 1], axis=1))
    label = "minimum norm" if ridge == 0 else f"ridge {ridge:g}"
    print(f"{label:13s} test error: " + " ".join(f"{p}:{e:.2f}" for p, e in zip(ps, dd[ridge][0])))

fig, ax = plt.subplots(1, 2, figsize=(9, 3.5))
for ridge, (err, mse) in dd.items():
    label = "minimum-norm least squares" if ridge == 0 else f"ridge, lambda = {ridge:g}"
    ax[0].semilogx(ps, err, "o-", label=label)
    ax[1].loglog(ps, mse, "o-", label=label)
for a in ax:
    a.axvline(200, color="gray", ls=":")
    a.set_xlabel("number of random features p (dotted: p = n = 200)")
ax[0].set(title="Test error", ylabel="classification error")
ax[1].set(title="Test squared error (median of 5 draws)", ylabel="squared error")
ax[0].legend(fontsize=8); plt.tight_layout(); plt.show()

4. The edge of stability¶

Classical optimization theory says gradient descent with step size η is stable on a quadratic only if its curvature is below 2/η. Cohen et al. (2021) measured the sharpness (the largest eigenvalue of the Hessian of the training loss) during full-batch gradient descent on neural networks. It rises during training (progressive sharpening) until it reaches about 2/η, and then it hovers there while the loss keeps going down, though not monotonically.

We use 500 digits, a tanh MLP and the squared loss, as in many of their experiments. The sharpness is computed by power iteration with Hessian-vector products: autograd can compute H·v without ever building H.

sub = torch.randperm(len(X_all), generator=torch.Generator().manual_seed(0))[:500]
Xe = X_all[sub]; Xe = (Xe - Xe.mean(0)) / (Xe.std(0) + 1e-3)
Ye = F.one_hot(y_all[sub], 10).float()

def tanh_mlp(seed=0, width=64):
    torch.manual_seed(seed)
    return nn.Sequential(nn.Linear(64, width), nn.Tanh(), nn.Linear(width, width), nn.Tanh(), nn.Linear(width, 10))

def full_loss(model):
    return 0.5 * ((model(Xe) - Ye) ** 2).sum(1).mean()

def sharpness(model, iters=20):
    params = list(model.parameters())
    grads = torch.autograd.grad(full_loss(model), params, create_graph=True)
    v = [torch.randn_like(p) for p in params]
    for _ in range(iters):                                    # power iteration: v <- Hv / |Hv|
        norm = torch.sqrt(sum((vi ** 2).sum() for vi in v))
        v = [vi / norm for vi in v]
        Hv = torch.autograd.grad(grads, params, grad_outputs=v, retain_graph=True)
        eig = sum((h * vi).sum() for h, vi in zip(Hv, v)).item()   # Rayleigh quotient v.Hv
        v = [h.detach() for h in Hv]
    return eig

eos = {}
for lr in [0.15, 0.3, 0.6]:
    model = tanh_mlp()
    losses, sharp = [], []
    for step in range(2001):
        if step % 50 == 0:
            sharp.append((step, sharpness(model)))
        loss = full_loss(model)
        model.zero_grad(); loss.backward()
        with torch.no_grad():
            for p in model.parameters():
                p -= lr * p.grad                              # plain full-batch gradient descent
        losses.append(loss.item())
    eos[lr] = (losses, sharp)
    late = [s for t, s in sharp if t >= 1000]
    ups = sum(b > a for a, b in zip(losses, losses[1:]))
    print(f"step size {lr}: 2/eta = {2 / lr:5.2f} | sharpness at start {sharp[0][1]:.2f}, mean over steps 1000-2000 "
          f"{np.mean(late):5.2f} | final loss {losses[-1]:.4f} | loss went up on {ups} of 2000 steps")

fig, ax = plt.subplots(1, 2, figsize=(9, 3.5))
for lr, (losses, sharp) in eos.items():
    line, = ax[0].plot([t for t, _ in sharp], [s for _, s in sharp], label=f"eta = {lr}")
    ax[0].axhline(2 / lr, color=line.get_color(), ls="--", lw=1)
    ax[1].plot(losses, color=line.get_color(), lw=1, label=f"eta = {lr}")
ax[0].set(title="Sharpness (dashed: 2/eta)", xlabel="step", ylabel="top Hessian eigenvalue")
ax[1].set(title="Training loss", xlabel="step", ylabel="squared loss", yscale="log")
ax[0].legend(fontsize=8); plt.tight_layout(); plt.show()

5. Sharpness-aware minimization (SAM) with noisy labels¶

SAM (Foret et al. 2021) looks for weights whose whole neighbourhood has low loss. Each step it moves to the nearby point w + ε with ε = ρ·g/‖g‖ (roughly the worst point within distance ρ), computes the gradient there, and applies that gradient at w. It costs two forward-backward passes per step. Foret et al. reported gains on image benchmarks and strong robustness to noisy labels. We flip about 30% of the training labels and compare SGD with SAM at two values of ρ, three seeds each, measuring accuracy on the clean test set.

g = torch.Generator().manual_seed(2)
flip = torch.rand(len(ytr), generator=g) < 0.3
y_noisy = torch.where(flip, torch.randint(0, 10, (len(ytr),), generator=g), ytr)
print(f"wrong training labels: {(y_noisy != ytr).float().mean():.2f}")

def train_sam(rho, seed, epochs=60, lr=0.05):
    model = mlp(seed)
    params = list(model.parameters())
    opt = torch.optim.SGD(params, lr=lr, momentum=0.9)
    gen = torch.Generator().manual_seed(seed)
    for epoch in range(epochs):
        for idx in torch.randperm(len(Xtr), generator=gen).split(64):
            loss = F.cross_entropy(model(Xtr[idx]), y_noisy[idx])
            opt.zero_grad(); loss.backward()
            if rho > 0:
                with torch.no_grad():
                    gnorm = torch.sqrt(sum((p.grad ** 2).sum() for p in params))
                    eps = [rho * p.grad / (gnorm + 1e-12) for p in params]
                    for p, e in zip(params, eps):
                        p.add_(e)                                   # climb to w + eps
                opt.zero_grad()
                F.cross_entropy(model(Xtr[idx]), y_noisy[idx]).backward()   # gradient at w + eps
                with torch.no_grad():
                    for p, e in zip(params, eps):
                        p.sub_(e)                                   # back to w, keep the new gradient
            opt.step()
    return accuracy(model, Xte, yte), accuracy(model, Xtr, y_noisy)

sam_results = {}
for rho in [0.0, 0.05, 0.1]:
    runs = [train_sam(rho, seed) for seed in range(3)]
    sam_results[rho] = runs
    tests = [r[0] for r in runs]
    name = "SGD" if rho == 0 else f"SAM rho={rho}"
    print(f"{name:13s} clean test accuracy {np.mean(tests):.3f} +/- {np.std(tests):.3f} "
          f"(seeds: {', '.join(f'{t:.3f}' for t in tests)}) | fits {np.mean([r[1] for r in runs]):.3f} of the noisy labels")

6. Lottery tickets¶

Frankle & Carbin (2019): train a network, remove the smallest-magnitude weights, rewind the surviving weights to their original initial values, and train again; repeat. The sparse subnetworks found this way ('winning tickets') train to the original accuracy, while the same sparse structure with a fresh random initialization does worse. We prune 50% of the remaining weights of each hidden layer per round (25% for the output layer) and compare the ticket with a random re-initialization of the same mask.

def train_masked(init_state, masks, epochs=15, seed=0):
    model = mlp(0)
    model.load_state_dict(init_state)
    weights = [model[0].weight, model[2].weight, model[4].weight]
    opt = torch.optim.Adam(model.parameters(), lr=1e-3)
    gen = torch.Generator().manual_seed(seed)
    with torch.no_grad():
        for w, m in zip(weights, masks): w.mul_(m)
    for epoch in range(epochs):
        for idx in torch.randperm(len(Xtr), generator=gen).split(64):
            loss = F.cross_entropy(model(Xtr[idx]), ytr[idx])
            opt.zero_grad(); loss.backward(); opt.step()
            with torch.no_grad():
                for w, m in zip(weights, masks): w.mul_(m)        # pruned weights stay at zero
    return model, accuracy(model, Xte, yte)

init_state = {k: v.clone() for k, v in mlp(0).state_dict().items()}
fresh_state = {k: v.clone() for k, v in mlp(123).state_dict().items()}       # a different random initialization
masks = [torch.ones_like(init_state[k]) for k in ["0.weight", "2.weight", "4.weight"]]
lottery = []
for rnd in range(7):
    model, acc_ticket = train_masked(init_state, masks)
    _, acc_fresh = train_masked(fresh_state, masks)
    remaining = sum(m.sum().item() for m in masks) / sum(m.numel() for m in masks)
    lottery.append((remaining, acc_ticket, acc_fresh))
    print(f"round {rnd}: {100 * remaining:5.1f}% of weights left | ticket {acc_ticket:.3f} | same mask, new init {acc_fresh:.3f}")
    new_masks = []
    for j, (w, m) in enumerate(zip([model[0].weight, model[2].weight, model[4].weight], masks)):
        rate = 0.25 if j == 2 else 0.5
        alive = w.detach().abs()[m.bool()]
        threshold = alive.kthvalue(int(rate * alive.numel())).values
        new_masks.append(m * (w.detach().abs() > threshold).float())
    masks = new_masks
print(f"finding the last ticket took {len(lottery)} full training runs")

r, a_t, a_f = zip(*lottery)

What to notice¶

  • Memorization (section 2). The same network and optimizer reached 99.9% training accuracy on the true labels by epoch 12 and on random labels by epoch 64. Test accuracy was 0.973 with true labels and 0.129 with random labels (chance is 0.10). So capacity alone cannot explain generalization: this network can memorize noise, yet on real labels it found a solution that generalizes.
  • Double descent (section 3). With minimum-norm least squares the test error was 0.30 at p = 50, peaked at 0.85 at p = n = 200, and fell back to 0.30 at p = 2,000; the squared error peaked even more sharply. With ridge λ = 100 the peak disappeared (test error 0.14 to 0.17 for every p from 100 up). The peak comes from fitting noisy labels exactly with a model that has just enough parameters to do so; enough regularization removes it, as Nakkiran et al. (2021) showed. It is not a reason to prefer huge models without regularization: the ridge models were better everywhere.
  • Edge of stability (section 4). For η = 0.3 and 0.6 the sharpness rose from 2.37 to 2/η and stayed there (mean 6.67 against 2/η = 6.67, and 3.37 against 3.33), while the loss kept falling with many small upward jumps (on 654 and 835 of 2,000 steps). For η = 0.15 the sharpness was still rising at step 2,000 (11.21, below 2/η = 13.33) and the loss never went up.
  • SAM (section 5): no gain here. SGD reached 0.778 ± 0.016 clean test accuracy; SAM gave 0.776 ± 0.034 (ρ = 0.05) and 0.765 ± 0.002 (ρ = 0.1). This goes against the gains Foret et al. reported with ResNets on CIFAR. With an MLP on 1,347 digits, three seeds and no tuning of ρ, the learning rate or the number of epochs, we do not see the benefit. SAM did memorize slightly fewer wrong labels (it fitted 0.992 and 0.979 of the noisy labels, against 1.000 for SGD).
  • Lottery tickets (section 6). Down to about 26% of the weights, the ticket and the re-initialized mask were within 0.01 of each other. Below that the original initialization mattered: 0.980 against 0.967 at 13.4%, 0.969 against 0.938 at 3.8%, and 0.956 against 0.873 at 2.1%. Finding the last ticket took 7 full training runs, so tickets tell us something about trainability but do not by themselves make training cheaper.
  • Limits. One small dataset, small MLPs and mostly one seed. Except for SAM, the results agree with the papers in direction, not in size.
